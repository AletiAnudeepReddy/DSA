# 4000. Largest Integer With Given Digit Sum

**Difficulty:** Easy  
**Topic:** Greedy, Math

---

## Problem Statement

You are given two non-negative integers:

- `n` → the maximum number of digits allowed.
- `s` → the required sum of digits.

Return the **largest possible integer** having **at most `n` digits** whose digits sum to `s`.

If no such integer exists, return `-1`.

---

## Approach: Greedy

### Intuition

To obtain the **largest possible number**, we should place the **largest digits at the most significant positions** (leftmost digits).

Since the largest possible digit is **9**, at every position we greedily place:

```
min(9, remainingSum)
```

Then subtract that digit from the remaining sum and continue.

If the required sum is larger than the maximum possible digit sum:

```
9 × n
```

then it is impossible to construct such a number.

---

## Why does Greedy Work?

The leftmost digit contributes the most to the value of the number.

For example,

```
900 > 090
```

Even though both numbers have the same digit sum.

Therefore, we should always place the **largest available digit** as early as possible.

This greedy choice always produces the largest possible integer.

---

## Algorithm

1. If

```
s > 9 × n
```

return `-1`.

2. Initialize `ans = 0`.

3. For each of the `n` positions:
   - Choose

```
digit = min(9, s)
```

   - Append the digit to the answer.
   - Reduce

```
s -= digit
```

4. Return the constructed number.

---

## Code (Java)

```java
class Solution {
    public int largestInteger(int n, int s) {

        if (s > 9 * n) {
            return -1;
        }

        int ans = 0;

        for (int i = 0; i < n; i++) {

            int digit = Math.min(9, s);

            ans = ans * 10 + digit;

            s -= digit;
        }

        return ans;
    }
}
```

# Key Takeaway

To maximize the value of the integer:

- Always place the **largest possible digit (`9`)** in the leftmost available position.
- Continue filling the remaining positions with the remaining digit sum.
- If the required sum exceeds `9 × n`, no valid number can be formed.

This greedy strategy guarantees the **largest possible integer** while using only a single traversal.

2029. Stone Game IX
Problem

You are given an array stones.

Alice and Bob take turns removing one stone.

After each removal, consider the sum of all removed stones:

If the sum becomes divisible by 3, the player who made that move loses immediately.
If all stones are removed without anyone losing, Bob wins automatically.

Alice starts first.

Return true if Alice can force a win, otherwise return false.

Example
Input: stones = [2,1]
Output: true

One possible game:

Alice removes 2
sum = 2


Bob removes 1
sum = 3

Bob's move makes the sum divisible by 3, so Bob loses.

Therefore:

Alice wins → true
Key Observation: Only Remainders Matter

We do not need the actual values of the stones.

For divisibility by 3, only the remainder matters:

x % 3

Every stone belongs to one of three groups:

Remainder	Meaning
0	Doesn't change the sum modulo 3
1	Adds 1 modulo 3
2	Adds 2 modulo 3

So we count:

cnt0 = number of stones where x % 3 == 0
cnt1 = number of stones where x % 3 == 1
cnt2 = number of stones where x % 3 == 2
How the Game Works

Suppose the current sum has remainder:

0

Then:

Picking remainder 1 → sum becomes 1
Picking remainder 2 → sum becomes 2
Picking remainder 0 → sum remains 0

But picking a stone that makes the sum 0 causes the current player to lose.

The important interaction is between remainder 1 and remainder 2:

0 + 1 = 1
1 + 2 = 0  ❌
0 + 2 = 2
2 + 1 = 0  ❌

So players are essentially forced to alternate between 1 and 2 stones.

What About Remainder-0 Stones?

A remainder-0 stone does not change the current remainder:

sum % 3 = 1


1 + 0 = 1

or

sum % 3 = 2


2 + 0 = 2

Therefore, 0-remainder stones mainly affect whose turn it is.

The parity of cnt0 becomes important.

Case 1: cnt0 is Even
if (cnt0 % 2 == 0)

The remainder-0 stones can effectively be paired between the players.

For Alice to have a winning strategy, there must be at least one remainder-1 stone and at least one remainder-2 stone:

cnt1 > 0 && cnt2 > 0

Why?

Alice needs to start the game with one type and Bob is forced into the other type. This allows Alice to control the modulo sequence and eventually force Bob to make the losing move.

Therefore:

if (cnt0 % 2 == 0) {
    return cnt1 > 0 && cnt2 > 0;
}
Case 2: cnt0 is Odd

Now the remainder-0 stones give one player an extra turn.

The balance between remainder 1 and remainder 2 becomes important.

Alice wins only when:

|cnt1 - cnt2| > 2

So:

return Math.abs(cnt1 - cnt2) > 2;

If the counts are too balanced, Bob can respond to Alice's moves and eventually force Alice to take a stone that makes the sum divisible by 3.

Complete Logic

Therefore:

If cnt0 is even:
    Alice wins if cnt1 > 0 AND cnt2 > 0


If cnt0 is odd:
    Alice wins if |cnt1 - cnt2| > 2

Java Code
class Solution {


    public boolean stoneGameIX(int[] stones) {


        int cnt0 = 0;
        int cnt1 = 0;
        int cnt2 = 0;


        for (int x : stones) {


            if (x % 3 == 0) {
                cnt0++;
            } 
            else if (x % 3 == 1) {
                cnt1++;
            } 
            else {
                cnt2++;
            }
        }


        // Even number of remainder-0 stones
        if (cnt0 % 2 == 0) {
            return cnt1 > 0 && cnt2 > 0;
        }


        // Odd number of remainder-0 stones
        return Math.abs(cnt1 - cnt2) > 2;
    }
}
Why Don't We Need DP?

At first glance, this looks like a game DP problem because:

Alice makes a move.
Bob makes a move.
Both play optimally.
The state changes after every move.

A brute-force approach could try every possible stone:

choose a stone
    ↓
Bob chooses a stone
    ↓
Alice chooses a stone
    ↓
...

That would have an enormous number of states.

The important optimization is recognizing that the actual values don't matter.

Only:

x % 3

matters.

Once we compress all stones into the three counts:

cnt0
cnt1
cnt2

the entire game can be characterized using the two conditions above.

Complexity

Let:

n = stones.length
Time Complexity

We scan the array once:

O(n)
Space Complexity

Only three counters are used:

O(1)
Important Pattern to Remember

This problem is a good example of state compression using modulo.

Whenever a problem says something like:

"The sum is divisible by 3"

immediately think:

Only sum % 3 matters.

Instead of storing actual values:

5, 8, 11, 14...

we can group them as:

remainder 0
remainder 1
remainder 2

So the huge game state gets compressed into just:

cnt0, cnt1, cnt2

The final winning condition is:

if (cnt0 % 2 == 0)
    return cnt1 > 0 && cnt2 > 0;


return Math.abs(cnt1 - cnt2) > 2;

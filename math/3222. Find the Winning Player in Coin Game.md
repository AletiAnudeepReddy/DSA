# 3222. Find the Winning Player in Coin Game

**Difficulty:** Easy  
**Topics:** Greedy, Game Theory, Math, Simulation

---

## Problem Statement

Alice and Bob are playing a game.

- There are:
  - `x` coins of value **75**
  - `y` coins of value **10**
- Alice starts first.
- On every turn, a player **must** pick coins totaling **115**.
- The only possible way to make **115** is:

```
75 + 10 + 10 + 10 + 10
```

which means each move consumes:

- **1 coin of 75**
- **4 coins of 10**

If a player cannot make 115, they lose.

Return the winner assuming both players play optimally.

---

# Approach 1: Simulation (Greedy)

## Intuition

Since there is only **one possible move**, there are no choices to make.

Every turn:

- Remove one 75-value coin.
- Remove four 10-value coins.

Alternate turns until a move is impossible.

The player who cannot make a move loses.

---

## Algorithm

1. Start with Alice.
2. While at least:
   - one 75-value coin
   - four 10-value coins
3. Perform one move.
4. Switch the player.
5. When no move is possible, return the previous player as the winner.

---

## Code (Java)

```java
class Solution {
    public String winningPlayer(int x, int y) {

        boolean alice = true;

        while (x >= 1 && y >= 4) {
            x--;
            y -= 4;
            alice = !alice;
        }

        return alice ? "Bob" : "Alice";
    }
}
```

---

### Complexity

- **Time:** O(min(x, y/4))
- **Space:** O(1)

---

# Approach 2: Mathematical Observation (Optimal)

## Key Observation

Every move always consumes

```
1 coin of 75
4 coins of 10
```

Therefore, the maximum possible number of moves is

```
min(x, y / 4)
```

because

- you cannot use more 75-value coins than available.
- you cannot use more groups of four 10-value coins than available.

---

## Winner

Let

```
moves = min(x, y / 4)
```

If

```
moves = 0
```

Alice cannot even make the first move.

Bob wins.

Otherwise,

Players alternate turns.

```
Move 1 → Alice
Move 2 → Bob
Move 3 → Alice
Move 4 → Bob
...
```

Therefore,

- **Odd number of moves → Alice makes the last move → Alice wins**
- **Even number of moves → Bob makes the last move → Bob wins**

---

## Algorithm

1. Compute

```
moves = min(x, y / 4)
```

2. If moves is odd

```
Alice
```

Else

```
Bob
```

---

## Code (Java)

```java
class Solution {
    public String winningPlayer(int x, int y) {

        int moves = Math.min(x, y / 4);

        return (moves % 2 == 0) ? "Bob" : "Alice";
    }
}
```

---

### Complexity

- **Time:** O(1)
- **Space:** O(1)

# Key Insight

There is **only one valid move** in the game:

```
1 × 75
+
4 × 10
=
115
```

So instead of simulating every turn, simply count how many moves are possible.

```
moves = min(x, y / 4)
```

The winner depends only on whether this number is **odd or even**.

---

# Interview Tips

- Since every turn has only one possible move, this is **not** a minimax problem.
- Convert the game into counting the total number of valid moves.
- Once the move count is known, determine the winner using parity (odd/even).
- This is a common **Game Theory + Mathematical Observation** pattern where optimal play reduces to analyzing the parity of total moves.

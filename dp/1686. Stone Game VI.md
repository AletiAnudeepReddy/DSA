# 1686. Stone Game VI

**Difficulty:** Medium  
**Topics:** Greedy, Sorting, Game Theory

---

# Problem Statement

Alice and Bob are playing a game with `n` stones.

Each stone has two values:

- `aliceValues[i]` → points Alice gets if she picks it.
- `bobValues[i]` → points Bob gets if he picks it.

Rules:

- Alice picks first.
- Players alternate turns.
- Once a stone is taken, it disappears.
- Both players play optimally.

Return

- **1** if Alice wins.
- **-1** if Bob wins.
- **0** if the game ends in a draw.

---

# Key Observation

This problem looks like a DP/Game Theory problem, but the optimal solution is actually **Greedy**.

The important question is:

> Which stone should be picked first?

Suppose a stone has

```
Alice = 8
Bob = 7
```

If Alice picks it

```
Alice gains 8.
```

If Alice leaves it,

Bob may pick it and gain

```
7.
```

So choosing this stone not only gives Alice **8 points**, but also prevents Bob from getting **7 points**.

Overall swing:

```
+8 for Alice
-7 for Bob

Net advantage = 15
```

This is exactly

```
AliceValue + BobValue
```

Therefore,

the importance of a stone is

```
aliceValues[i] + bobValues[i]
```

The larger this sum,

the more valuable it is for **both players**.

Hence everyone wants to grab the stones with the largest total value first.

---

# Greedy Strategy

For every stone compute

```
importance = aliceValue + bobValue
```

Sort all stones in **descending order** of this importance.

Then simulate the game.

- Alice picks 0th, 2nd, 4th...
- Bob picks 1st, 3rd, 5th...

Finally compare scores.

---

# Why Does This Work?

Suppose there are two stones.

```
Stone A

Alice = 8
Bob = 7

Sum = 15
```

```
Stone B

Alice = 9
Bob = 1

Sum = 10
```

If Alice ignores Stone A,

Bob gets

```
7
```

If Alice takes Stone A,

Alice gets

```
8
```

The swing is

```
8+7 = 15
```

which is larger than

```
9+1 = 10
```

Therefore Stone A is strategically more important.

This exchange argument proves sorting by

```
AliceValue + BobValue
```

is optimal.

---

# Algorithm

1. Create an array storing

```
Alice Value
Bob Value
Total Value
```

2. Sort descending by

```
Alice + Bob
```

3. Alternate turns.

- Alice adds her value.
- Bob adds his value.

4. Compare scores.

---

# Code

```java
class Solution {

    public int stoneGameVI(int[] aliceValues, int[] bobValues) {

        int n=aliceValues.length;

        int[][] stones=new int[n][3];

        for(int i=0;i<n;i++){

            stones[i][0]=aliceValues[i];

            stones[i][1]=bobValues[i];

            stones[i][2]=aliceValues[i]+bobValues[i];
        }

        Arrays.sort(stones,(a,b)->b[2]-a[2]);

        int alice=0;

        int bob=0;

        for(int i=0;i<n;i++){

            if(i%2==0){

                alice+=stones[i][0];

            }else{

                bob+=stones[i][1];
            }
        }

        if(alice>bob)
            return 1;

        if(bob>alice)
            return -1;

        return 0;
    }
}
```

# Why Sort by Sum Instead of Alice's Value?

Suppose

```
Stone A

Alice = 10

Bob = 0
```

```
Stone B

Alice = 7

Bob = 8
```

If Alice only considers her own value,

she picks

```
10
```

But Bob now gets

```
8
```

Stone B had total importance

```
15
```

while Stone A had

```
10
```

Ignoring the opponent's value can lead to a worse overall outcome.

Sorting by the total value accounts for both gaining your own points and denying your opponent.

# Key Takeaways

- This is **not** an Interval DP problem.
- Every stone has value for **both** players.
- Picking a stone both:
  - Increases your score.
  - Prevents your opponent from scoring.
- Therefore each stone's importance is

```
aliceValue + bobValue
```

- Greedy strategy:
  1. Compute `alice + bob`.
  2. Sort in descending order.
  3. Alternate picks.
  4. Compare final scores.

This "sort by combined value" is the core greedy insight and is what makes the solution optimal.

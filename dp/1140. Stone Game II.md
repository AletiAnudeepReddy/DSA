# 1140. Stone Game II

**Difficulty:** Medium  
**Topics:** Dynamic Programming, Game Theory, Minimax

---

# Problem Statement

Alice and Bob are playing another stone game.

- There are `n` piles.
- Initially `M = 1`.
- On each turn, a player may take the first `X` remaining piles, where

```
1 <= X <= 2M
```

- After taking `X` piles,

```
M = max(M, X)
```

- Both players play optimally.

Return the **maximum number of stones Alice can collect**.

---

# Key Observation

Unlike previous Stone Games, here we **do not only care about winning**.

We need to maximize

```
Alice's total stones
```

instead of simply determining the winner.

A very useful trick is to use a **suffix sum array**.

---

# Why Suffix Sum?

Suppose we are currently at index

```
i
```

The remaining stones are

```
piles[i...n-1]
```

Let

```
suffix[i]
```

be the total stones remaining.

Example

```
piles = [2,7,9,4,4]

suffix

i=0 -> 26
i=1 -> 24
i=2 -> 17
i=3 -> 8
i=4 -> 4
```

Now if the opponent can obtain

```
opponent
```

stones from these remaining piles,

then the current player automatically gets

```
suffix[i] - opponent
```

This completely removes the need to explicitly compute the current player's score.

---

# DP State

Let

```
dp(i,M)
```

represent

> Maximum stones the current player can collect starting from index `i` with current value `M`.

Answer

```
dp(0,1)
```

---

# Recurrence

Current player may choose

```
X = 1 ... 2M
```

After taking

```
X
```

piles,

Opponent plays optimally.

Opponent can obtain

```
dp(i+X,max(M,X))
```

Total remaining stones are

```
suffix[i]
```

Therefore current player's stones become

```
suffix[i] - opponent
```

Transition

```
dp(i,M)=
max(
    suffix[i]-dp(i+X,max(M,X))
)
```

for every

```
1<=X<=2M
```

---

# Base Case

If the current player can take **all remaining piles**

```
2*M >= remaining piles
```

then

```
return suffix[i]
```

because taking everything is always optimal.

---

# Approach 1: Pure Recursion

## Intuition

At every state

```
(i,M)
```

try every possible

```
X
```

Choose the move that maximizes

```
remaining stones - opponent's answer
```

---

## Algorithm

1. Compute suffix sums.
2. Start from

```
(i=0,M=1)
```

3. Try every valid

```
X
```

4. Return the maximum answer.

---

## Code

```java
class Solution {

    int[] suffix;
    int n;

    public int stoneGameII(int[] piles) {

        n = piles.length;

        suffix = new int[n];

        suffix[n - 1] = piles[n - 1];

        for(int i=n-2;i>=0;i--){

            suffix[i]=piles[i]+suffix[i+1];
        }

        return recur(0,1);
    }

    public int recur(int i,int M){

        if(i>=n)
            return 0;

        if(2*M>=n-i)
            return suffix[i];

        int ans=0;

        for(int X=1;X<=2*M;X++){

            ans=Math.max(ans,
                    suffix[i]-recur(i+X,Math.max(M,X)));
        }

        return ans;
    }
}
```

---

## Complexity

- **Time:** Exponential
- **Space:** O(n)

---

# Approach 2: Memoization (Top-Down DP)

## Intuition

Many states

```
(i,M)
```

are computed repeatedly.

Store every answer in

```
dp[i][M]
```

so each state is solved only once.

---

## Code

```java
class Solution {

    int[][] dp;

    int[] suffix;

    int n;

    public int stoneGameII(int[] piles) {

        n=piles.length;

        dp=new int[n][n+1];

        suffix=new int[n];

        suffix[n-1]=piles[n-1];

        for(int i=n-2;i>=0;i--){

            suffix[i]=piles[i]+suffix[i+1];
        }

        return recur(0,1);
    }

    public int recur(int i,int M){

        if(i>=n)
            return 0;

        if(2*M>=n-i)
            return suffix[i];

        if(dp[i][M]!=0)
            return dp[i][M];

        int ans=0;

        for(int X=1;X<=2*M;X++){

            ans=Math.max(ans,
                    suffix[i]-recur(i+X,Math.max(M,X)));
        }

        return dp[i][M]=ans;
    }
}
```

---

## Complexity

There are

- `n` choices of `i`
- at most `n` values of `M`

Each state tries at most

```
2M <= 2n
```

moves.

- **Time:** O(n³)
- **Space:** O(n²)

For `n ≤ 100`, this easily passes.

# Why Do We Subtract?

Suppose remaining stones are

```
100
```

If the opponent can collect

```
42
```

then the current player automatically gets

```
100-42=58
```

So instead of separately computing both scores,

we only compute

```
Opponent's best score
```

Then

```
Current score = Total Remaining − Opponent Score
```

This greatly simplifies the DP.

| Approach | Idea | Time | Space |
|----------|------|------|-------|
| Recursion | Try every possible move | Exponential | O(n) |
| Memoization | Cache `(index, M)` states | O(n³) | O(n²) |

# Key Takeaways

- This is a **Game Theory + Dynamic Programming** problem.
- State is determined by:
  - Current index `i`
  - Current value `M`
- Suffix sums allow us to know the total remaining stones instantly.
- Transition:

```
dp(i,M)=
max(
    suffix[i]-dp(i+X,max(M,X))
)
```

for every

```
1<=X<=2M
```

- Base case:

```
If 2*M >= remaining piles

Take everything.

Return suffix[i].
```

The main insight is that instead of directly maximizing the current player's score, we maximize **`Total Remaining − Opponent's Best Score`**, which naturally models optimal play for both players.

1510. Stone Game IV
Problem

Alice and Bob play a game with n stones.

Alice plays first.
On each turn, a player can remove any non-zero perfect square number of stones.
A player who cannot make a move loses.
Both players play optimally.

Return true if Alice can force a win, otherwise false.

Key Idea — Game DP

This is a classic Winning State / Losing State DP problem.

For every number of stones n, define:

win(n) = true

if the current player can force a win with n stones.

Otherwise:

win(n) = false
Base Case

If there are 0 stones:

win(0) = false

Because there is no valid move, so the current player loses.

The Important Game Theory Idea

Suppose we are at n stones.

We can remove:

1, 4, 9, 16, ...

as long as the square is <= n.

After removing square, the opponent gets:

n - square

stones.

If we can find even one move such that the opponent is in a losing state:

win(n - square) == false

then the current player wins.

Therefore:

win(n) = true
if there exists a square such that win(n - square) == false

If every possible move gives the opponent a winning state, then:

win(n) = false
General Pattern

This is the most important pattern to remember:

I win if I can make the opponent lose.

In code:

if (!win(n - square)) {
    return true;
}
Approach 1 — Pure Recursion
class Solution {
    private boolean win(int n) {
        if (n == 0) return false;

        for (int i = 1; i * i <= n; i++) {
            int square = i * i;

            if (!win(n - square)) {
                return true;
            }
        }

        return false;
    }

    public boolean winnerSquareGame(int n) {
        return win(n);
    }
}
How it works

For example, consider:

n = 2

Alice can only remove 1.

2 -> 1

Now Bob has 1 stone.

Bob removes 1:

1 -> 0

Alice has no move.

Therefore:

win(1) = true
win(2) = false
Recursion Tree for n = 4

Alice can choose:

4
|
+-- remove 1 --> 3
|
+-- remove 4 --> 0

If Alice removes 4:

4 -> 0

Bob has no move.

Therefore:

win(4) = true
Why if (!win(...))?

This line is the heart of the solution:

if (!win(n - square)) {
    return true;
}

Suppose:

win(3) = false

Then from 4, Alice can remove 1:

4 -> 3

Bob receives a losing state.

Therefore Alice wins.

Approach 2 — Recursion + Memoization

The pure recursive solution recalculates the same states many times.

For example:

win(10)
   |
   +-- win(9)
   +-- win(6)
   +-- win(1)

Those states can be reached from different paths.

So we store already-computed results.

class Solution {
    Boolean[] dp;

    public boolean win(int n) {
        if (n == 0) return false;

        if (dp[n] != null) {
            return dp[n];
        }

        for (int i = 1; i * i <= n; i++) {
            int square = i * i;

            if (!win(n - square)) {
                return dp[n] = true;
            }
        }

        return dp[n] = false;
    }

    public boolean winnerSquareGame(int n) {
        dp = new Boolean[n + 1];
        return win(n);
    }
}
Why Boolean[] instead of boolean[]?

We need to distinguish between:

State has not been calculated

and

State was calculated as false

With:

Boolean[] dp;

we have three possible values:

null  -> not calculated
true  -> winning state
false -> losing state

So:

if (dp[n] != null)

means the answer is already available.

DP State

We only need one parameter:

n

So:

dp[n]

represents:

Whether the current player can win when there are n stones remaining.

Example DP States

Starting from:

n = 5

Possible moves:

5 - 1 = 4
5 - 4 = 1

We know:

win(1) = true
win(4) = true

So:

win(5) = false

because every possible move gives the opponent a winning state.

Winning / Losing State Table

The first few states are:

n	Result	Reason
0	Lose	No move
1	Win	Remove 1
2	Lose	Only move → 1
3	Win	Remove 1 → 2
4	Win	Remove 4 → 0
5	Lose	Moves → 4 or 1, both winning
6	Win	Remove 1 → 5
7	Lose	Moves → 6 or 3, both winning
8	Win	Remove 1 → 7
9	Win	Remove 9 → 0

The pattern isn't simply alternating because the available moves are:

1, 4, 9, 16, ...
Complexity

For each state n, we try every perfect square:

1², 2², 3², ..., √n²

So there are approximately:

√n

possible moves.

There are n states.

Time
O(n√n)
Space
O(n)

for the memoization array and recursion stack.

Why Greedy Doesn't Work

You might think:

Always remove the largest possible square.

That doesn't work.

For example:

n = 5

Largest square:

4

would leave:

1

for the opponent.

But 1 is a winning state.

Instead, removing 1 leaves:

5 -> 4

and 4 is a winning state too.

So 5 is actually a losing state.

The correct strategy depends on whether the resulting state is winning or losing, not simply on the size of the square we remove.

Important Pattern to Remember

This problem is a standard two-player optimal game DP.

The template is:

boolean win(state) {

    if (terminal state)
        return false;

    for (every possible move) {

        nextState = makeMove(state);

        if (!win(nextState)) {
            return true;
        }
    }

    return false;
}

The logic is:

If I have at least one move
that puts my opponent in a losing state,
I win.

Otherwise, I lose.

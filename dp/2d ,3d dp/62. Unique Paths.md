62. Unique Paths
Problem

You are given an m x n grid.

A robot starts at:

(0, 0)

and needs to reach:

(m - 1, n - 1)

The robot can move only:

Right → (i, j + 1)
Down → (i + 1, j)

Return the total number of unique paths.

Example
m = 3, n = 2

The grid is:

(0,0) → (0,1)
  ↓        ↓
(1,0) → (1,1)
  ↓        ↓
(2,0) → (2,1)

There are 3 paths:

Right → Down → Down
Down → Right → Down
Down → Down → Right

Answer:

3
Intuition

At every cell (i, j), the robot has at most two choices:

             (i,j)
             /   \
          Down   Right
           ↓       →

Therefore, the number of paths from (i, j) is:

paths(i, j) =
    paths(i + 1, j)
    +
    paths(i, j + 1)

We keep doing this until we reach the destination.

1. Recursive Solution
Base Cases
Reached destination

If:

i == m - 1 && j == n - 1

we found one valid path.

So:

return 1;
Went outside the grid

If:

i >= m || j >= n

this is not a valid path.

So:

return 0;
Code
class Solution {

    public int recur(int i, int j, int m, int n) {

        // Reached destination
        if (i == m - 1 && j == n - 1) {
            return 1;
        }

        // Went outside the grid
        if (i >= m || j >= n) {
            return 0;
        }

        // Move down + move right
        return recur(i + 1, j, m, n)
             + recur(i, j + 1, m, n);
    }

    public int uniquePaths(int m, int n) {
        return recur(0, 0, m, n);
    }
}
Dry Run — Recursion

Consider:

m = 3
n = 2

Start:

recur(0,0)

From (0,0):

recur(0,0)
├── recur(1,0)   // Down
└── recur(0,1)   // Right
From (1,0)
recur(1,0)
├── recur(2,0)
└── recur(1,1)

From (2,0):

recur(2,0)
└── recur(2,1)

(2,1) is the destination:

return 1

From (1,1):

recur(1,1)
└── recur(2,1)

Again destination:

return 1

Therefore:

recur(1,0) = 1 + 1 = 2
From (0,1)
recur(0,1)
├── recur(1,1)
└── recur(0,2)

recur(1,1) gives:

1

recur(0,2) is outside the grid:

0

Therefore:

recur(0,1) = 1 + 0 = 1

Finally:

recur(0,0)
= recur(1,0) + recur(0,1)
= 2 + 1
= 3

Answer:

3
Problem With Recursion

The recursive solution calculates the same cells multiple times.

For example:

recur(1,1)

can be reached from multiple paths.

So we have overlapping subproblems.

This makes the recursion exponential.

The natural solution is Dynamic Programming.

2. Memoization — Top Down DP

We create:

int[][] dp = new int[m][n];

where:

dp[i][j] = number of unique paths from (i,j) to destination

Before calculating a cell, check whether we already calculated it:

if (dp[i][j] > 0) {
    return dp[i][j];
}

Then store the result:

dp[i][j] =
    recur(i + 1, j, m, n, dp)
    +
    recur(i, j + 1, m, n, dp);
Code
class Solution {

    public int recur(
            int i,
            int j,
            int m,
            int n,
            int[][] dp) {

        // Reached destination
        if (i == m - 1 && j == n - 1) {
            return 1;
        }

        // Outside grid
        if (i >= m || j >= n) {
            return 0;
        }

        // Already calculated
        if (dp[i][j] > 0) {
            return dp[i][j];
        }

        // Down + Right
        return dp[i][j] =
            recur(i + 1, j, m, n, dp)
            +
            recur(i, j + 1, m, n, dp);
    }

    public int uniquePaths(int m, int n) {

        int[][] dp = new int[m][n];

        return recur(0, 0, m, n, dp);
    }
}
DP Dry Run

For:

m = 3
n = 3

The DP table eventually becomes:

1  3  1
3  2  1
1  1  1

Why?

The destination always has one path:

dp[2][2] = 1

For (2,1):

dp[2][1] = dp[2][2]
         = 1

For (1,2):

dp[1][2] = dp[2][2]
         = 1

For (1,1):

dp[1][1] = dp[2][1] + dp[1][2]
         = 1 + 1
         = 2

For (0,1):

dp[0][1] = dp[1][1] + dp[0][2]
         = 2 + 1
         = 3

Finally:

dp[0][0] = dp[1][0] + dp[0][1]
         = 3 + 3
         = 6

So:

Answer = 6
Why Memoization Is Better

Without DP:

Same cells
   ↓
calculated repeatedly
   ↓
exponential time

With memoization:

First time → calculate
Second time → directly use dp[i][j]

There are only:

m × n

different states.

Therefore, every state is calculated at most once.

Complexity
Recursive Solution

The number of recursive calls grows exponentially.

Time:  O(2^(m+n))
Space: O(m+n)

O(m+n) is the maximum recursion depth.

Memoization Solution

There are m × n states, and each state performs constant work.

Time:  O(m × n)
Space: O(m × n)

The space consists of:

dp array → O(m × n)
recursion stack → O(m + n)

So overall:

Space = O(m × n)
Important DP Pattern

This problem is a classic Grid DP problem.

At every cell:

        (i,j)
       /     \
    Down    Right

The recurrence is:

dp[i][j] = dp[i+1][j] + dp[i][j+1]

with:

destination → 1
outside grid → 0
Pattern to remember

Whenever a grid problem says:

"How many ways can I reach the destination?"

and gives a limited number of movements, think:

Current cell
     ↓
Possible moves
     ↓
Sum of answers of those moves

For this problem:

dp[i][j] = down + right

This same grid DP + recursion + memoization pattern becomes very useful in problems such as Unique Paths II, Minimum Path Sum, and many other 2D DP problems.

64. Minimum Path Sum
Problem

You are given an m x n grid containing non-negative integers.

The robot starts at the top-left cell:

(0, 0)

and must reach the bottom-right cell:

(m - 1, n - 1)

It can move only:

Down → (i + 1, j)
Right → (i, j + 1)

Return the minimum possible sum of all values along the path.

Example
grid = [
    [1, 3, 1],
    [1, 5, 1],
    [4, 2, 1]
]

The minimum path is:

1 → 3 → 1 → 1 → 1

Therefore:

1 + 3 + 1 + 1 + 1 = 7

Answer:

7
Intuition

This is very similar to 62. Unique Paths.

In Unique Paths, we asked:

How many ways can I reach this cell?

Here we ask:

What is the minimum cost to reach this cell?

Instead of adding the number of paths, we take the minimum of the possible paths.

For a cell (i, j), there are two possible ways to reach it:

        (i-1,j)
            ↓
          (i,j)
            ↑
        (i,j-1)

So:

minimumPath(i,j)
=
grid[i][j]
+
min(
    minimumPath(i-1,j),
    minimumPath(i,j-1)
)
Recursive Approach

We start from the destination:

(m-1, n-1)

and recursively move up or left.

Why?

Because if we are currently at (i,j), the previous cell must have been either:

(i-1,j)  → came from above

or:

(i,j-1)  → came from left

Therefore:

up   = recur(i-1, j)
left = recur(i, j-1)

answer = grid[i][j] + min(up, left)
Base Cases
1. Starting cell

When we reach:

i == 0 && j == 0

we are at the starting point.

There is only one way to reach it, and its cost is:

grid[0][0]

So:

if (i == 0 && j == 0)
    return grid[0][0];
2. Outside the grid

If:

i < 0

or:

j < 0

we have gone outside the grid.

That path is invalid.

We return:

Integer.MAX_VALUE

This represents an impossible path.

Recursive Code
class Solution {

    private int recur(int i, int j, int[][] grid) {

        // Reached starting cell
        if (i == 0 && j == 0) {
            return grid[0][0];
        }

        // Outside the grid
        if (i < 0 || j < 0) {
            return Integer.MAX_VALUE;
        }

        // Come from above
        int up = recur(i - 1, j, grid);

        // Come from left
        int left = recur(i, j - 1, grid);

        int min = Math.min(up, left);

        // Both paths are invalid
        if (min == Integer.MAX_VALUE) {
            return min;
        }

        return grid[i][j] + min;
    }

    public int minPathSum(int[][] grid) {

        int n = grid.length;
        int m = grid[0].length;

        return recur(n - 1, m - 1, grid);
    }
}
Why Do We Check Integer.MAX_VALUE?

Consider the first row.

For example:

[1, 3, 1]

At (0,2), we can only come from the left.

The up call becomes:

recur(-1, 2)

which returns:

Integer.MAX_VALUE

If we directly did:

grid[i][j] + min

there is a potential integer overflow when min is Integer.MAX_VALUE.

Therefore, your check:

if (min == Integer.MAX_VALUE)
    return min;

protects against that.

Dry Run

Consider:

grid = [
    [1, 3, 1],
    [1, 5, 1],
    [4, 2, 1]
]

We start at:

recur(2,2)

The two possibilities are:

recur(1,2)
       ↓
recur(2,1)

Let's calculate from the starting point.

(0,0)
dp[0][0] = 1
(0,1)

Only left is valid:

3 + 1 = 4
(0,2)
1 + 4 = 5
(1,0)

Only above is valid:

1 + 1 = 2
(1,1)

Two choices:

up   = 4
left = 2

Choose the minimum:

5 + min(4,2)
= 5 + 2
= 7
(1,2)
up   = 5
left = 7

Therefore:

1 + min(5,7)
= 6
(2,0)
4 + 2 = 6
(2,1)
up   = 7
left = 6

Therefore:

2 + min(7,6)
= 8
(2,2)
up   = 6
left = 8

Therefore:

1 + min(6,8)
= 7

Final answer:

7
Problem With Plain Recursion

The recursive solution has overlapping subproblems.

For example, a cell such as:

(1,1)

can be reached through multiple recursive paths.

So it gets calculated multiple times.

This leads to exponential time.

The solution is memoization.

Memoization / Top-Down DP

We create:

int[][] dp = new int[n][m];

Meaning:

dp[i][j]
=
minimum path sum from (0,0) to (i,j)

Whenever we calculate a cell, store the result.

Before calculating:

if (dp[i][j] > 0)
    return dp[i][j];

Since all grid values are non-negative and every valid path has a positive sum except the possible all-zero case, > 0 works here for this problem. A more general implementation can use a separate visited array or initialize dp with -1.

Memoization Code
class Solution {

    private int recur(
            int i,
            int j,
            int[][] grid,
            int[][] dp) {

        // Reached starting cell
        if (i == 0 && j == 0) {
            return grid[0][0];
        }

        // Outside the grid
        if (i < 0 || j < 0) {
            return Integer.MAX_VALUE;
        }

        // Already calculated
        if (dp[i][j] > 0) {
            return dp[i][j];
        }

        // From above
        int up = recur(i - 1, j, grid, dp);

        // From left
        int left = recur(i, j - 1, grid, dp);

        int min = Math.min(up, left);

        if (min == Integer.MAX_VALUE) {
            return min;
        }

        return dp[i][j] = grid[i][j] + min;
    }

    public int minPathSum(int[][] grid) {

        int n = grid.length;
        int m = grid[0].length;

        int[][] dp = new int[n][m];

        return recur(n - 1, m - 1, grid, dp);
    }
}
DP Table

For:

[
 [1,3,1],
 [1,5,1],
 [4,2,1]
]

The minimum path sum for every cell is:

1   4   5
2   7   6
6   8   7

So:

dp[2][2] = 7

which is our answer.

Recurrence

The most important formula to remember is:

dp[i][j] = grid[i][j] + min(
    dp[i-1][j],
    dp[i][j-1]
)
Base case
dp[0][0] = grid[0][0]
Complexity
Plain Recursion

Because the same cells are calculated repeatedly:

Time:  O(2^(m+n))
Space: O(m+n)

O(m+n) is the maximum recursion depth.

Memoization

There are only m × n unique states.

Each state is calculated once.

Time:  O(m × n)
Space: O(m × n)

The space includes the DP table and recursion stack, with the DP table dominating.

Connection With 62. Unique Paths

These two problems are excellent to learn together.

62. Unique Paths

Question:

How many ways can I reach this cell?

Recurrence:

dp[i][j] = dp[i-1][j] + dp[i][j-1]
64. Minimum Path Sum

Question:

What is the minimum cost to reach this cell?

Recurrence:

dp[i][j] = grid[i][j] + min(
    dp[i-1][j],
    dp[i][j-1]
)

So the key difference is:

Unique Paths:
        SUM

Minimum Path Sum:
        MIN

This is an important grid DP pattern:

Identify what the state represents, then combine the results from the possible previous states using the operation required by the problem.

# 877. Stone Game

**Difficulty:** Medium  
**Topics:** Dynamic Programming, Game Theory, Minimax, Memoization

---

## Problem Statement

Alice and Bob are playing a game with an even number of piles.

- On each turn, a player picks either the **leftmost** or **rightmost** pile.
- Both players play **optimally**.
- The player with more stones at the end wins.

Return **true** if Alice wins, otherwise **false**.

---

# Approach 1: Minimax Recursion (Brute Force)

## Intuition

This is the most straightforward simulation.

We keep:

- Alice's score
- Bob's score
- Current turn
- Remaining interval `[start...end]`

### Alice's Turn

She wants **at least one move** that lets her win.

So,

```
return left || right
```

### Bob's Turn

Bob also plays optimally.

If **either move** makes Alice lose, Bob will choose it.

Therefore Alice wins only if she wins after **both** Bob's choices.

```
return left && right
```

---

## Algorithm

1. If no piles remain:
   - return whether Alice's score > Bob's score.

2. If Alice's turn:
   - Pick left
   - Pick right
   - Return OR.

3. If Bob's turn:
   - Pick left
   - Pick right
   - Return AND.

---

## Code

```java
class Solution {
    public boolean recur(int s,int e,int[] piles,int alice,int bob,int turn){
        if(s>e){
            return alice>bob;
        }

        if(turn==0){
            boolean left=recur(s+1,e,piles,alice+piles[s],bob,1);
            boolean right=recur(s,e-1,piles,alice+piles[e],bob,1);
            return left||right;
        }else{
            boolean left=recur(s+1,e,piles,alice,bob+piles[s],0);
            boolean right=recur(s,e-1,piles,alice,bob+piles[e],0);
            return left&&right;
        }
    }

    public boolean stoneGame(int[] piles) {
        return recur(0,piles.length-1,piles,0,0,0);
    }
}
```

---

## Complexity

- **Time:** O(2ⁿ)
- **Space:** O(n)

---

# Approach 2: Score Difference Recursion

## Key Observation

Instead of tracking two scores separately,

track only

```
(current player's score)
-
(opponent's score)
```

Suppose current player chooses left.

He gains

```
piles[left]
```

Then opponent plays optimally.

Opponent's advantage is

```
recur(left+1,right)
```

Therefore current player's final advantage is

```
piles[left] - recur(left+1,right)
```

Similarly,

```
piles[right] - recur(left,right-1)
```

Take the better one.

---

## Formula

```
dp(l,r)=
max(
    piles[l]-dp(l+1,r),
    piles[r]-dp(l,r-1)
)
```

If final score difference is non-negative,

Alice can win.

---

## Code

```java
class Solution {

    public int recur(int start,int end,int[] nums){

        if(start>end)
            return 0;

        int pickLeft=nums[start]-recur(start+1,end,nums);

        int pickRight=nums[end]-recur(start,end-1,nums);

        return Math.max(pickLeft,pickRight);
    }

    public boolean stoneGame(int[] piles) {
        return recur(0,piles.length-1,piles)>=0;
    }
}
```

---

## Complexity

- **Time:** O(2ⁿ)
- **Space:** O(n)

---

# Approach 3: Memoization (Top-Down DP)

## Intuition

The recursion repeatedly computes the same interval.

Example:

```
dp(2,5)
```

may be reached through multiple paths.

Store answers in

```
dp[start][end]
```

so every interval is solved only once.

---

## Code

```java
class Solution {

    public int recur(int start,int end,int[] nums,Integer[][] dp){

        if(start>end)
            return 0;

        if(dp[start][end]!=null)
            return dp[start][end];

        int pickLeft=nums[start]-recur(start+1,end,nums,dp);

        int pickRight=nums[end]-recur(start,end-1,nums,dp);

        return dp[start][end]=Math.max(pickLeft,pickRight);
    }

    public boolean stoneGame(int[] piles) {

        int n=piles.length;

        Integer[][] dp=new Integer[n][n];

        return recur(0,n-1,piles,dp)>=0;
    }
}
```

---

## Complexity

- **Time:** O(n²)
- **Space:** O(n²)

# Approach 4: Bottom-Up DP (Tabulation)

## Idea

Build the answer from smaller intervals.

### Base Case

Single pile

```
dp[i][i]=piles[i]
```

because current player simply takes it.

---

### Transition

For every interval

```
[start...end]
```

Current player has two options.

Pick left

```
piles[start]-dp[start+1][end]
```

Pick right

```
piles[end]-dp[start][end-1]
```

Take the maximum.

---

## Filling Order

We first compute

```
Length = 1
```

then

```
Length = 2
```

then

```
Length = 3
```

...

until

```
Length = n
```

---

## Code

```java
class Solution {

    public boolean stoneGame(int[] piles) {

        int n=piles.length;

        int[][] dp=new int[n][n];

        for(int i=0;i<n;i++)
            dp[i][i]=piles[i];

        for(int len=2;len<=n;len++){

            for(int start=0;start<=n-len;start++){

                int end=start+len-1;

                int pickLeft=piles[start]-dp[start+1][end];

                int pickRight=piles[end]-dp[start][end-1];

                dp[start][end]=Math.max(pickLeft,pickRight);
            }
        }

        return dp[0][n-1]>=0;
    }
}
```

---

## Complexity

- **Time:** O(n²)
- **Space:** O(n²)

---

# DP State Explanation

Let

```
dp[l][r]
```

represent

> **Maximum score difference (Current Player − Opponent)** obtainable from the subarray `[l...r]`.

Example

```
piles = [5,3,4,5]
```

For interval

```
[3,4]
```

Current player can

Take 3

Difference

```
3 - dp(...)
```

or

Take 4

Difference

```
4 - dp(...)
```

Whichever gives larger difference is optimal.

---

# Why Subtract DP?

Suppose current player picks

```
7
```

Then the opponent becomes the "current player".

If opponent can obtain an advantage of

```
5
```

then our net advantage becomes

```
7 - 5 = 2
```

That is why every transition is

```
pickedValue - opponentAdvantage
```

---

# Comparison

| Approach | Idea | Time | Space |
|----------|------|------|-------|
| Brute Force | Simulate both players' scores | O(2ⁿ) | O(n) |
| Score Difference | Minimax using score difference | O(2ⁿ) | O(n) |
| Memoization | Cache interval results | O(n²) | O(n²) |
| Tabulation | Bottom-up interval DP | O(n²) | O(n²) |

---

# Key Takeaways

- This is a classic **Game Theory + Interval DP** problem.
- Instead of tracking both players' scores, track the **score difference**.
- Transition:

```
dp(l,r)=max(
    piles[l]-dp(l+1,r),
    piles[r]-dp(l,r-1)
)
```

- If

```
dp(0,n-1) >= 0
```

Alice can guarantee a win.

  - Stone Game II

213. House Robber II
Problem

You are given an array nums where each element represents the money in a house.

Unlike House Robber I, the houses are arranged in a circle.

That means:

0 and n-1 are also adjacent

So you cannot rob both the first and last house.

Return the maximum amount of money you can rob without robbing two adjacent houses.

Example
nums = [2,3,2]

Because the houses are circular:

2 -- 3 -- 2
|          |
+----------+

We cannot choose both nums[0] and nums[2].

Therefore:

Answer = 3
Intuition

The circular arrangement creates one extra restriction:

We cannot rob both the first and last house.

So we divide the problem into two independent cases.

Case 1: Don't rob the first house

Consider:

nums[1 ... n-1]

Now the first house is excluded, so there is no circular problem.

Case 2: Don't rob the last house

Consider:

nums[0 ... n-2]

Now the last house is excluded.

Therefore:

answer = max(
    rob(nums[0 ... n-2]),
    rob(nums[1 ... n-1])
)

For each case, we use the same DP logic from House Robber I.

Why Do We Split Into Two Cases?

Suppose:

nums = [1,2,3,1]

The first and last houses are adjacent.

We have two possibilities:

Case 1: Exclude first
[2,3,1]

Case 2: Exclude last
[1,2,3]

We solve both:

rob([2,3,1]) = 3
rob([1,2,3]) = 4

Therefore:

answer = max(3,4)
       = 4
Optimized House Robber DP

We don't actually need a dp[] array.

We only need two variables:

prev2 = dp[i-2]
prev  = dp[i-1]

For every house:

pick = nums[i] + prev2
notPick = prev

curr = max(pick, notPick)

Then move forward:

prev2 = prev
prev = curr

This reduces space from O(n) to O(1).

Code
class Solution {

    // Solves normal House Robber for a linear array
    public int robs(int[] nums) {

        int n = nums.length;

        int prev = nums[0];
        int prev2 = 0;

        for (int i = 1; i < n; i++) {

            // Pick current house
            int pick = nums[i];

            if (i > 1) {
                pick += prev2;
            }

            // Don't pick current house
            int notPick = prev;

            int curr = Math.max(pick, notPick);

            prev2 = prev;
            prev = curr;
        }

        return prev;
    }

    public int rob(int[] nums) {

        int n = nums.length;

        // Only one house
        if (n == 1) {
            return nums[0];
        }

        // Case 1: Exclude first house
        int[] temp1 = new int[n - 1];

        // Case 2: Exclude last house
        int[] temp2 = new int[n - 1];

        for (int i = 0; i < n; i++) {

            // nums[1 ... n-1]
            if (i != 0) {
                temp1[i - 1] = nums[i];
            }

            // nums[0 ... n-2]
            if (i != n - 1) {
                temp2[i] = nums[i];
            }
        }

        int res1 = robs(temp1);
        int res2 = robs(temp2);

        return Math.max(res1, res2);
    }
}

Complexity

Let n = nums.length.

We create two arrays of size n - 1.

Time

Each case is processed once:

O(n) + O(n)
= O(n)
Space

Two temporary arrays:

O(n)

The DP itself uses only:

O(1)

So the overall space complexity of your implementation is O(n) because of temp1 and temp2.

Can We Reduce Space to O(1)?

Yes.

We don't actually need to create temp1 and temp2.

We can directly tell the helper which range to process:

class Solution {

    private int robRange(int[] nums, int start, int end) {

        int prev2 = 0;
        int prev = 0;

        for (int i = start; i <= end; i++) {

            int pick = nums[i] + prev2;
            int notPick = prev;

            int curr = Math.max(pick, notPick);

            prev2 = prev;
            prev = curr;
        }

        return prev;
    }

    public int rob(int[] nums) {

        int n = nums.length;

        if (n == 1) {
            return nums[0];
        }

        // Case 1: exclude last
        int case1 = robRange(nums, 0, n - 2);

        // Case 2: exclude first
        int case2 = robRange(nums, 1, n - 1);

        return Math.max(case1, case2);
    }
}

This is the version I would prefer in an interview because it avoids creating the two temporary arrays.

Complexity of optimized version
Time:  O(n)
Space: O(1)
Key Pattern to Remember
House Robber I

Linear:

dp[i] = max(
    nums[i] + dp[i-2],
    dp[i-1]
)
House Robber II

Circular:

Don't take first
        ↓
[1 ... n-1]

Don't take last
        ↓
[0 ... n-2]

answer = max(two cases)

The most important insight is:

For a circular DP problem where the first and last elements conflict, break the circle into two linear cases: exclude the first OR exclude the last.

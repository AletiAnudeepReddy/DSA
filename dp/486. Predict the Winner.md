# 486. Predict the Winner

**Difficulty:** Medium  
**Topics:** Dynamic Programming, Recursion, Game Theory, Minimax, Memoization

---

## Problem Statement

Two players are playing a game on an integer array.

- Players take turns picking either the **leftmost** or **rightmost** number.
- Player 1 starts first.
- Both players play **optimally**.
- Each chosen number is added to the player's score.

Return **true** if Player 1 can win (or tie), otherwise return **false**.

---

## Approach 1: Brute Force Minimax (Track Both Scores)

### Intuition

Simulate the game exactly.

- Player 1 tries to maximize his chance of winning.
- Player 2 also plays optimally to minimize Player 1's chance.

Maintain:

- Current left index
- Current right index
- Player 1 score
- Player 2 score
- Whose turn it is

When Player 1's turn:
- Try both left and right.
- If **any** choice leads to victory → return true.

When Player 2's turn:
- Player 2 also plays optimally.
- Player 1 wins only if **both** choices still allow him to win.

---

### Algorithm

1. If no numbers remain, compare scores.
2. If Player 1's turn:
   - Pick left.
   - Pick right.
   - Return OR of both.
3. If Player 2's turn:
   - Pick left.
   - Pick right.
   - Return AND of both.

---

### Code (Java)

```java
class Solution {
    public boolean recur(int start,int end,int p1,int p2,int turn,int[] nums){
        if(start>end){
            return p1>=p2;
        }

        if(turn==0){
            boolean left=recur(start+1,end,p1+nums[start],p2,1,nums);
            boolean right=recur(start,end-1,p1+nums[end],p2,1,nums);
            return left||right;
        }
        else{
            boolean left=recur(start+1,end,p1,p2+nums[start],0,nums);
            boolean right=recur(start,end-1,p1,p2+nums[end],0,nums);
            return left&&right;
        }
    }

    public boolean predictTheWinner(int[] nums) {
        return recur(0,nums.length-1,0,0,0,nums);
    }
}
```

---

### Complexity

- **Time:** O(2ⁿ)
- **Space:** O(n)

# Approach 2: Optimal Recursive Score Difference

## Key Observation

Instead of tracking **two scores**, track only the **score difference**.

Suppose

```
current player's score - opponent's score
```

If the value is positive, current player is winning.

If negative, opponent is winning.

---

### DP State

```
recur(start,end)
```

returns

```
Maximum score difference
(current player - opponent)
```

for subarray

```
[start...end]
```

---

### Transition

If current player picks left

```
nums[start] - recur(start+1,end)
```

Why subtraction?

Because after taking the left element,

the opponent becomes the current player.

So opponent's advantage must be subtracted.

Similarly,

```
nums[end] - recur(start,end-1)
```

Take the better choice.

```
max(left,right)
```

---

### Example

```
nums = [1,5,2]
```

Player picks

```
1
```

Opponent gains

```
recur(5,2)
```

Net gain

```
1 - recur(...)
```

Exactly captures optimal play.

---

### Algorithm

1. Base case

```
start==end
```

Return that number.

2. Compute

```
pickLeft
pickRight
```

3. Return maximum difference.

4. Final answer

```
difference >= 0
```

---

### Code (Java)

```java
class Solution {

    public int recur(int start,int end,int[] nums){

        if(start==end)
            return nums[start];

        int pickLeft=nums[start]-recur(start+1,end,nums);
        int pickRight=nums[end]-recur(start,end-1,nums);

        return Math.max(pickLeft,pickRight);
    }

    public boolean predictTheWinner(int[] nums) {
        return recur(0,nums.length-1,nums)>=0;
    }
}
```

---

### Complexity

- **Time:** O(2ⁿ)
- **Space:** O(n)

---

# Approach 3: Memoization (Top-Down DP)

## Intuition

The recursive solution repeatedly solves the same subproblems.

Example:

```
recur(2,5)
```

may be computed many times.

Store the result once.

---

### DP State

```
dp[start][end]
```

stores

```
Maximum score difference
```

for interval

```
[start...end]
```

---

### Transition

Exactly same as Approach 2.

```
pickLeft =
nums[start] - recur(start+1,end)

pickRight =
nums[end] - recur(start,end-1)

dp[start][end]=max(...)
```

---

### Code (Java)

```java
class Solution {

    public int recur(int start,int end,int[] nums,Integer[][] dp){

        if(start==end)
            return nums[start];

        if(dp[start][end]!=null)
            return dp[start][end];

        int pickLeft=nums[start]-recur(start+1,end,nums,dp);
        int pickRight=nums[end]-recur(start,end-1,nums,dp);

        return dp[start][end]=Math.max(pickLeft,pickRight);
    }

    public boolean predictTheWinner(int[] nums) {

        int n=nums.length;
        Integer[][] dp=new Integer[n][n];

        return recur(0,n-1,nums,dp)>=0;
    }
}
```

---

### Complexity

- **Time:** O(n²)
- **Space:** O(n²)

# Dry Run

```
nums = [1,5,2]
```

```
recur(0,2)

Pick Left

1 - recur(1,2)

Pick Right

2 - recur(0,1)
```

Eventually,

```
Difference = -2
```

Since

```
-2 < 0
```

Player 1 loses.

Answer:

```
false
```

# Key Insight

Instead of tracking two separate scores,

track only:

```
Current Player Score − Opponent Score
```

At every move:

```
Take Current Number
−
Opponent's Best Possible Difference
```

This simple transformation reduces the game into a classic interval DP problem.

---

# Interview Tips

- Approach 1 demonstrates understanding of **Minimax recursion** but is exponential.
- Approach 2 introduces the crucial **score-difference transformation**, eliminating the need to track both players' scores.
- Approach 3 optimizes the recursion with **memoization**, reducing the time complexity to **O(n²)**.
- The same score-difference DP pattern appears in many two-player optimal-play problems, such as **Stone Game**, **Optimal Strategy for a Game**, and similar interval DP questions.

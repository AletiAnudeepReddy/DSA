# 1406. Stone Game III

**Difficulty:** Hard  
**Topics:** Dynamic Programming, Game Theory, Minimax

---

# Problem Statement

Alice and Bob are playing another stone game.

- Stones are arranged in a row.
- Each stone has a value (can even be **negative**).
- On each turn, a player may take **1, 2, or 3 stones** from the beginning of the remaining row.
- Both players play **optimally**.

Return:

- `"Alice"` if Alice wins.
- `"Bob"` if Bob wins.
- `"Tie"` if both finish with the same score.

---

# Key Observation

Instead of storing both players' scores separately, we only store

> **Maximum score difference (Current Player − Opponent)**

This is exactly the same idea used in:

- Predict the Winner (486)
- Stone Game (877)

Suppose the current player takes stones worth

```
sum
```

The opponent will then obtain an optimal score difference of

```
recur(nextIndex)
```

So the current player's net advantage becomes

```
sum - recur(nextIndex)
```

We simply maximize this over taking 1, 2, or 3 stones.

---

# DP State

Let

```
dp[i]
```

represent

> Maximum score difference the current player can achieve starting from index `i`.

Answer is

```
dp[0]
```

If

```
dp[0] > 0
```

Alice wins.

If

```
dp[0] < 0
```

Bob wins.

Otherwise

```
Tie
```

---

# Recurrence

Try taking

- 1 stone
- 2 stones
- 3 stones

```
dp[i] = max(
    sum(1 stone) - dp[i+1],
    sum(2 stones) - dp[i+2],
    sum(3 stones) - dp[i+3]
)
```

---

# Approach 1: Pure Recursion

## Intuition

At every position,

try taking

- first stone
- first two stones
- first three stones

and choose the move producing the maximum score difference.

---

## Algorithm

For every index

```
i
```

Try

```
take 1
take 2
take 3
```

Compute

```
currentSum - opponentDifference
```

Return the maximum.

---

## Code

```java
class Solution {

    public int recur(int i,int[] stoneValue){

        if(i>=stoneValue.length){
            return 0;
        }

        int best=Integer.MIN_VALUE;
        int sum=0;

        for(int k=0;k<3&&i+k<stoneValue.length;k++){

            sum+=stoneValue[i+k];

            best=Math.max(best,
                    sum-recur(i+k+1,stoneValue));
        }

        return best;
    }

    public String stoneGameIII(int[] stoneValue) {

        int ans=recur(0,stoneValue);

        if(ans>0) return "Alice";

        if(ans<0) return "Bob";

        return "Tie";
    }
}
```

---

## Complexity

- **Time:** O(3ⁿ)
- **Space:** O(n)

---

# Approach 2: Memoization (Top-Down DP)

## Intuition

The recursion repeatedly computes the same state.

Example

```
recur(5)
```

may be reached from several paths.

Store every computed answer in

```
memo[i]
```

so each index is solved only once.

---

## Code

```java
class Solution {

    Integer[] memo;

    public int recur(int i,int[] stoneValue){

        if(i>=stoneValue.length){
            return 0;
        }

        if(memo[i]!=null)
            return memo[i];

        int best=Integer.MIN_VALUE;

        int sum=0;

        for(int k=0;k<3&&i+k<stoneValue.length;k++){

            sum+=stoneValue[i+k];

            best=Math.max(best,
                    sum-recur(i+k+1,stoneValue));
        }

        return memo[i]=best;
    }

    public String stoneGameIII(int[] stoneValue) {

        memo=new Integer[stoneValue.length];

        int ans=recur(0,stoneValue);

        if(ans>0) return "Alice";

        if(ans<0) return "Bob";

        return "Tie";
    }
}
```

---

## Complexity

- **Time:** O(n)
- **Space:** O(n)

# Approach 3: Tabulation (Bottom-Up DP)

## Intuition

Instead of recursion,

compute answers from the end.

Suppose we're at

```
i
```

We already know

```
dp[i+1]
dp[i+2]
dp[i+3]
```

So we can directly calculate

```
dp[i]
```

---

## Filling Order

Compute

```
dp[n]=0
```

Then

```
n-1
n-2
...
0
```

---

## Code

```java
class Solution {

    public String stoneGameIII(int[] stoneValue) {

        int n=stoneValue.length;

        int[] dp=new int[n+1];

        for(int i=n-1;i>=0;i--){

            dp[i]=Integer.MIN_VALUE;

            int sum=0;

            for(int k=0;k<3&&i+k<n;k++){

                sum+=stoneValue[i+k];

                dp[i]=Math.max(dp[i],
                        sum-dp[i+k+1]);
            }
        }

        if(dp[0]>0)
            return "Alice";

        if(dp[0]<0)
            return "Bob";

        return "Tie";
    }
}
```

---

## Complexity

- **Time:** O(n)
- **Space:** O(n)

# Why Do We Subtract DP?

Suppose current player takes

```
sum = 15
```

Then opponent starts playing.

If opponent can gain an advantage of

```
8
```

then current player's final advantage is

```
15-8=7
```

Therefore every transition is

```
sum - opponentDifference
```

This is the standard **Minimax DP** idea.

# Key Takeaways

- This is a **Game Theory + Dynamic Programming** problem.
- Instead of tracking two scores, store the **score difference**.
- DP State:

```
dp[i] = maximum score difference current player can obtain from index i
```

- Transition:

```
dp[i] = max(
    take1 - dp[i+1],
    take2 - dp[i+2],
    take3 - dp[i+3]
)
```

- Final Answer:

```
dp[0] > 0  → Alice
dp[0] < 0  → Bob
dp[0] = 0  → Tie
```

This score-difference DP is one of the most common patterns in **Game Theory** problems on LeetCode.

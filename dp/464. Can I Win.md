# 464. Can I Win

**Difficulty:** Medium  
**Topics:** Dynamic Programming, Bitmasking, Recursion, Memoization, Game Theory, Minimax

---

## Problem Statement

Two players are playing a game.

- Numbers from **1 to maxChoosableInteger** are available.
- Every number can be chosen **only once**.
- Players alternate turns.
- Each chosen number is added to the running total.
- The player who makes the running total **greater than or equal to desiredTotal** wins.

Both players play optimally.

Return **true** if the first player can force a win.

---

# Approach 1: Brute Force (Backtracking + Minimax)

## Intuition

At every turn, the current player can choose any unused number.

For every possible choice:

- If picking that number immediately reaches the target → current player wins.
- Otherwise, let the opponent play optimally.
- If there exists **one move** that makes the opponent lose, then the current player wins.

This is a classic **Minimax** problem.

---

## Initial Observations

### Case 1

```
desiredTotal <= 0
```

The target is already reached.

The first player wins immediately.

---

### Case 2

Compute the maximum possible sum.

```
1 + 2 + ... + max
```

Formula

```
max × (max + 1) / 2
```

If

```
sum < desiredTotal
```

Even after using every number, the target cannot be reached.

Return

```
false
```

---

## Recursive State

Maintain

```
used[i]
```

which tells whether number `i` has already been chosen.

Current target becomes

```
remaining target
```

instead of maintaining the running sum.

---

## Transition

For every unused number

```
i
```

### Immediate Win

If

```
i >= target
```

Current player wins.

---

Otherwise

Choose it

```
used[i]=true
```

Opponent now plays

```
dfs(target-i)
```

Backtrack

```
used[i]=false
```

If opponent loses

Current player wins.

---

## Algorithm

1. Check impossible cases.
2. Try every unused number.
3. If any move makes opponent lose
   return true.
4. Otherwise return false.

---

## Code (Java)

```java
class Solution {

    public boolean canIWin(int maxChoosableInteger, int desiredTotal) {

        if (desiredTotal <= 0)
            return true;

        int sum = maxChoosableInteger * (maxChoosableInteger + 1) / 2;

        if (sum < desiredTotal)
            return false;

        boolean[] used = new boolean[maxChoosableInteger + 1];

        return dfs(used, desiredTotal);
    }

    private boolean dfs(boolean[] used, int target) {

        for (int i = 1; i < used.length; i++) {

            if (used[i])
                continue;

            if (i >= target)
                return true;

            used[i] = true;

            boolean opponentWins = dfs(used, target - i);

            used[i] = false;

            if (!opponentWins)
                return true;
        }

        return false;
    }
}
```

---

### Complexity

- **Time:** Exponential (approximately O(n!))
- **Space:** O(n)

This approach gets TLE.

# Approach 2: Memoization + Bitmasking (Optimal)

## Key Observation

The recursive solution repeatedly visits the same game states.

Example

```
Numbers used

1,4,6

can be reached through many different orders.
```

Instead of recomputing, store the result.

---

## Why Bitmask?

Instead of storing

```
boolean[] used
```

store one integer.

Example

```
Numbers

1 2 3 4
```

Mask

```
0101
```

means

```
1 used
2 unused
3 used
4 unused
```

Each bit represents whether a number has already been picked.

---

## DP State

```
dfs(mask,target)
```

returns

```
Can the current player win
```

from this state?

Notice something important.

The remaining target is uniquely determined by the chosen numbers represented in the mask, so memoizing by **mask alone** is sufficient.

---

## Transition

For every unused number

```
i
```

Bit

```
1<<(i-1)
```

If already used

Skip.

---

### Immediate Win

```
i >= target
```

Current player wins.

---

Otherwise

Opponent plays

```
dfs(mask | bit,
    target-i)
```

If opponent loses

Current player wins.

---

Store the answer inside

```
memo
```

---

## Code (Java)

```java
class Solution {

    private HashMap<Integer, Boolean> memo = new HashMap<>();

    public boolean canIWin(int maxChoosableInteger, int desiredTotal) {

        if (desiredTotal <= 0)
            return true;

        int sum = maxChoosableInteger * (maxChoosableInteger + 1) / 2;

        if (sum < desiredTotal)
            return false;

        return dfs(0, desiredTotal, maxChoosableInteger);
    }

    private boolean dfs(int mask, int target, int max) {

        if (memo.containsKey(mask))
            return memo.get(mask);

        for (int i = 1; i <= max; i++) {

            int bit = 1 << (i - 1);

            if ((mask & bit) != 0)
                continue;

            if (i >= target) {
                memo.put(mask, true);
                return true;
            }

            if (!dfs(mask | bit, target - i, max)) {
                memo.put(mask, true);
                return true;
            }
        }

        memo.put(mask, false);
        return false;
    }
}
```

---

### Complexity

- **Time:** O(2ⁿ × n)
- **Space:** O(2ⁿ)

where

```
n = maxChoosableInteger
```

Since

```
maxChoosableInteger ≤ 20
```

there are at most

```
2²⁰ ≈ 1,048,576
```

possible masks.

# Why Memoization Works

Without memoization

```
Mask

001101
```

may be reached through multiple different move orders.

Every time we recompute the entire subtree.

Memoization ensures

```
One mask
↓

Computed once

↓

Reused forever
```

This reduces exponential recursion dramatically.

---

# Key Insight

This is a classic **Game Theory + Minimax + Bitmask DP** problem.

The game state is completely determined by:

- Which numbers have already been used.
- The remaining target (which is implicitly determined by the mask).

If there exists **one move** that forces the opponent into a losing state,

then the current player wins.

# Interview Tips

- First check the impossible case using

```
sum = n(n+1)/2
```

- Represent the chosen numbers using a **bitmask** instead of a boolean array.
- Memoize each mask to avoid recomputation.
- This problem is one of the most common interview questions for **Bitmask DP + Minimax**.
- Similar problems include **Predict the Winner (486)**, **Stone Game**, **Flip Game II (294)**, and other optimal-play game theory questions.

# 2958. Length of Longest Subarray With at Most K Frequency

**Difficulty:** Medium
**Topics:** Array, HashMap, Sliding Window

---

## Problem

Given an integer array `nums` and an integer `k`, find the length of the longest contiguous subarray in which **every element appears at most `k` times**.

### Example

```text
nums = [1,2,3,1,2,3,1,2], k = 2

Answer = 6
```

The longest valid subarray is:

```text
[1,2,3,1,2,3]
```

Each number occurs exactly twice.

---

# Approach 1 — Standard Sliding Window

### Idea

Maintain a window:

```text
[l ........ r]
```

and a `HashMap` storing the frequency of every number inside the current window.

For every `nums[r]`:

1. Add `nums[r]` to the map.
2. If its frequency becomes greater than `k`, move `l` forward.
3. Decrease the frequency of every element removed from the window.
4. Update the maximum window length.

### Code

```java
class Solution {
    public int maxSubarrayLength(int[] nums, int k) {
        int n = nums.length;

        Map<Integer, Integer> mpp = new HashMap<>();

        int res = 0;
        int l = 0;
        int r = 0;

        while (r < n) {

            mpp.put(nums[r], mpp.getOrDefault(nums[r], 0) + 1);

            while (mpp.get(nums[r]) > k) {
                mpp.put(nums[l], mpp.get(nums[l]) - 1);
                l++;
            }

            res = Math.max(res, r - l + 1);

            r++;
        }

        return res;
    }
}
```

### Why does the `while` work?

Suppose:

```text
nums = [1,2,1]
k = 1
```

When `r` reaches the second `1`:

```text
window = [1,2,1]
frequency of 1 = 2
```

But:

```text
2 > k
```

So the window is invalid.

Move `l`:

```text
[1,2,1]
 ^
 l
```

Remove the first `1`:

```text
[2,1]
```

Now:

```text
frequency of 1 = 1
```

The window becomes valid again.

# Approach 2 — Using `Map.merge()`

This is a more compact version of the same sliding-window idea.

```java
class Solution {
    public int maxSubarrayLength(int[] nums, int k) {

        int n = nums.length;

        Map<Integer, Integer> mpp = new HashMap<>();

        int res = 0;
        int l = 0;
        int r = 0;

        while (r < n) {

            int num = nums[r++];

            if (mpp.merge(num, 1, Integer::sum) == k + 1) {

                int num2 = 0;

                do {
                    num2 = nums[l++];
                    mpp.merge(num2, -1, Integer::sum);

                } while (num2 != num);
            }

            res = Math.max(res, r - l);
        }

        return res;
    }
}
```

---

# Understanding `merge()`

The important line is:

```java
mpp.merge(num, 1, Integer::sum)
```

It means:

### If `num` does not exist

```java
mpp.put(num, 1);
```

### If `num` already exists

```java
mpp.put(num, mpp.get(num) + 1);
```

So:

```java
mpp.merge(num, 1, Integer::sum)
```

is essentially a compact way of writing:

```java
mpp.put(num, mpp.getOrDefault(num, 0) + 1);
```

---

## Why compare with `k + 1`?

```java
if (mpp.merge(num, 1, Integer::sum) == k + 1)
```

Suppose:

```text
k = 2
```

The allowed frequency is:

```text
1 → valid
2 → valid
3 → invalid
```

When we insert the third occurrence:

```text
merge() returns 3
```

which is:

```text
k + 1
```

Therefore, we know exactly when the window becomes invalid.

---

# Important Trick in Approach 2

Instead of:

```java
while (mpp.get(nums[r]) > k)
```

we know that the only problem is the newly inserted `num`.

So we remove elements from the left until we remove the **previous occurrence of `num`**.

```java
do {
    num2 = nums[l++];
    mpp.merge(num2, -1, Integer::sum);
} while (num2 != num);
```

Example:

```text
nums = [1, 2, 3, 1]
k = 1
```

Before adding the last `1`:

```text
[1, 2, 3]
```

Add `1`:

```text
[1, 2, 3, 1]
```

Frequency:

```text
1 → 2
```

Invalid.

Now remove from left:

```text
remove 1
```

Immediately the duplicate problem is solved:

```text
[2,3,1]
```

So we don't need to continue removing.

---

# Sliding Window Intuition

The most important thing to remember:

> **Expand with `r`, and whenever the window becomes invalid, shrink from `l` until it becomes valid again.**

For this problem:

```text
Condition:
frequency of every element <= k
```

Therefore:

```text
r → add element
l → remove elements when frequency becomes > k
```

Visualize it as:

```text
        r
        ↓
[ 1  2  3  1  2 ]
  ↑
  l
```

If adding another `1` causes:

```text
frequency(1) = k + 1
```

shrink:

```text
        r
        ↓
[ 1  2  3  1  2  1 ]
  ↑
  l
```

Remove from the left until the duplicate causing the violation is removed.

# Complexity

### Approach 1

Each element is:

* added to the window once
* removed from the window at most once

Therefore:

```text
Time:  O(n)
Space: O(n)
```

### Approach 2

Same complexity:

```text
Time:  O(n)
Space: O(n)
```

# Key Pattern to Remember

This problem is a classic **variable-size sliding window**.

Whenever you see:

> "Longest subarray satisfying some condition"

think:

```text
left = 0

for right = 0 → n-1:

    add nums[right]

    while window is invalid:
        remove nums[left]
        left++

    answer = max(answer, window size)
```

For this problem:

```text
Window invalid
        ↓
frequency of nums[right] > k
        ↓
move left
```

The most important invariant is:

> **After the shrinking step, the current window is always valid.**

Then:

```java
res = Math.max(res, r - l + 1);
```

is safe because we only calculate the answer using a valid window.

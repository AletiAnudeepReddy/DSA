556. Next Greater Element III

LeetCode 556 — Next Greater Element III

Solved
Medium
Topics: String, Two Pointers, Greedy

Problem

Given a positive integer n, find the smallest integer greater than n that contains exactly the same digits.

If no such number exists, return -1.

The result must also fit in a 32-bit signed integer.

Example
Input:  n = 12
Output: 21
Input:  n = 21
Output: -1
Approach — Next Permutation

This problem is essentially the Next Permutation algorithm applied to the digits of n.

We need to find the smallest permutation of the digits that is greater than the current number.

Key idea

For:

12354

We want the next larger permutation.

Step 1: Find the pivot

Traverse from right to left and find the first index i such that:

digits[i] < digits[i + 1]

For:

1 2 3 5 4
    ↑

3 < 5, so 3 is the pivot.

Everything after the pivot is in descending order.

Step 2: Find the smallest digit greater than the pivot

Search from the right side.

For:

1 2 3 5 4
    ↑

The first digit from the right greater than 3 is 4.

Swap them:

1 2 4 5 3
Step 3: Reverse the suffix

After the pivot, we want the smallest possible arrangement.

The suffix is:

5 3

Reverse it:

3 5

Final answer:

12435

This is the smallest number greater than 12354 using exactly the same digits.

Why do we reverse the suffix?

Before the swap, the suffix is guaranteed to be in descending order.

After swapping the pivot with the smallest possible larger digit, we need to make the remaining suffix as small as possible.

Therefore, reverse the descending suffix to make it ascending.

Important Edge Case

If we cannot find:

digits[i] < digits[i + 1]

then the entire number is in descending order.

For example:

54321

There is no larger permutation.

Therefore:

return -1;
Java Solution
class Solution {

    private void swap(char[] digits, int i, int j) {
        char temp = digits[i];
        digits[i] = digits[j];
        digits[j] = temp;
    }

    private void reverse(char[] digits, int start, int end) {
        while (start < end) {
            swap(digits, start, end);
            start++;
            end--;
        }
    }

    public int nextGreaterElement(int n) {

        char[] digits = String.valueOf(n).toCharArray();
        int m = digits.length;

        // Step 1: Find the pivot
        int ind = -1;

        for (int i = m - 2; i >= 0; i--) {
            if (digits[i] < digits[i + 1]) {
                ind = i;
                break;
            }
        }

        // No greater permutation exists
        if (ind == -1) {
            return -1;
        }

        // Step 2: Find the smallest digit greater than pivot
        for (int i = m - 1; i > ind; i--) {
            if (digits[i] > digits[ind]) {
                swap(digits, i, ind);
                break;
            }
        }

        // Step 3: Make suffix smallest
        reverse(digits, ind + 1, m - 1);

        // Check 32-bit integer limit
        long res = Long.parseLong(new String(digits));

        if (res > Integer.MAX_VALUE) {
            return -1;
        }

        return (int) res;
    }
}

Complexity

Let n be the number of digits.

Operation	Complexity
Find pivot	O(n)
Find successor	O(n)
Reverse suffix	O(n)
Total	O(n)
Extra space	O(n)

The O(n) space is mainly because we convert the integer into a char[].

Pattern to Remember

This is the standard Next Permutation pattern:

1. Find first decreasing position from right
       ↓
   nums[i] < nums[i+1]

2. Find smallest element on right greater than nums[i]

3. Swap

4. Reverse the suffix
One-line intuition

Make the number just slightly bigger at the rightmost possible position, then make everything after it as small as possible.

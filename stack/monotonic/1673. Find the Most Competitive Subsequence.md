# 1673. Find the Most Competitive Subsequence

**Difficulty:** Medium  
**Topics:** Greedy, Monotonic Stack

---

# Problem Statement

Given an integer array `nums` and an integer `k`, return the **most competitive subsequence** of size `k`.

A subsequence `A` is more competitive than another subsequence `B` if, at the first position where they differ, `A` has the smaller element.

---

# Intuition

The problem is very similar to:

- **316. Remove Duplicate Letters**
- **1081. Smallest Subsequence of Distinct Characters**

In those problems, we build the **lexicographically smallest string**.

Here, we build the **lexicographically smallest subsequence of length `k`**.

The greedy idea is:

- If the current element is smaller than the stack top, it should come earlier.
- Remove larger elements **only if we can still form a subsequence of size `k`** after removing them.

This is achieved using a **monotonic increasing stack**.

---

# Greedy Rule

While processing the current element:

```
Current < Stack Top
```

AND

```
After popping, enough elements remain to build a subsequence of size k
```

Then remove the stack top.

Condition:

```java
while (!stack.isEmpty()
       && curr < stack.peek()
       && (stack.size() - 1 + (n - i)) >= k)
```

---

# Understanding the Important Condition

```java
(stack.size() - 1 + (n - i)) >= k
```

This condition checks whether it is **safe to pop**.

After popping,

```
Remaining elements

=

(Stack Size - 1)

+

(Unprocessed Elements)
```

must still be at least `k`.

Otherwise, popping would make it impossible to build a subsequence of length `k`.

---

## Example

```
nums = [3,5,2,6]

k = 2
```

At index `2`

```
Current = 2

Stack

[3,5]
```

Since

```
2 < 5
```

Can we pop?

```
Stack Size - 1 = 1

Remaining Elements = 2

Total = 3

3 >= 2 ✅
```

Pop `5`

Stack

```
[3]
```

Again,

```
2 < 3
```

Can we pop?

```
0 + 2 = 2

2 >= 2 ✅
```

Pop `3`

Push `2`

```
[2]
```

Finally push `6`

```
[2,6]
```

Answer

```
[2,6]
```

# Dry Run

```
nums = [3,5,2,6]

k = 2
```

| Current | Stack | Action |
|----------|-------|--------|
| 3 | [3] | Push |
| 5 | [3,5] | Push |
| 2 | [2] | Pop 5, Pop 3, Push 2 |
| 6 | [2,6] | Push |

Answer

```
[2,6]
```

---

# Algorithm

1. Traverse the array.
2. While:
   - the stack is not empty,
   - the current element is smaller than the stack top,
   - and popping is safe,
   remove the stack top.
3. If the stack size is still less than `k`, push the current element.
4. The stack finally contains the most competitive subsequence.

---

## Complexity

- **Time Complexity:** `O(n)`
- **Space Complexity:** `O(k)`

Each element is pushed and popped at most once.

---

## Java Solution

```java
class Solution {

    public int[] mostCompetitive(int[] nums, int k) {

        Stack<Integer> stack = new Stack<>();
        int n = nums.length;

        for (int i = 0; i < n; i++) {

            int curr = nums[i];

            while (!stack.isEmpty()
                    && curr < stack.peek()
                    && (stack.size() - 1 + (n - i)) >= k) {

                stack.pop();
            }

            if (stack.size() < k) {
                stack.push(curr);
            }
        }

        int[] ans = new int[k];

        for (int i = 0; i < k; i++) {
            ans[i] = stack.get(i);
        }

        return ans;
    }
}
```

---

# Why `if (stack.size() < k)`?

Even after popping, we should **only keep the first `k` elements** in our answer.

If the stack already contains `k` elements,

```
Do not push the current element.
```

This guarantees that the final subsequence has exactly `k` elements.

---

# Key Takeaways

- This is a **Greedy + Monotonic Increasing Stack** problem.
- Similar to **316** and **1081**, but instead of removing duplicates, we must build a subsequence of **fixed length `k`**.
- Pop larger elements only when:
  - the current element is smaller, and
  - enough elements remain to complete the subsequence.
- The condition

  ```java
  (stack.size() - 1 + (n - i)) >= k
  ```

  ensures that popping is safe.
- Each element is pushed and popped at most once, resulting in an **`O(n)`** solution.

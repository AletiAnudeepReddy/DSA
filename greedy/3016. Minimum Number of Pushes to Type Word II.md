# 3016. Minimum Number of Pushes to Type Word II

**Difficulty:** Medium  
**Topics:** Greedy, Hashing, Sorting, Counting

---

## Problem

You are given a string `word` consisting of lowercase English letters.

A telephone keypad has **8 available keys (2–9)**. You are allowed to **remap** the letters to these keys in any way, but:

- Every letter must be assigned to exactly one key.
- A key can contain any number of letters.
- The first letter on a key requires **1 push**.
- The second letter requires **2 pushes**.
- The third letter requires **3 pushes**, and so on.

Unlike **Word I**, letters **can repeat** in the input.

Return the **minimum number of pushes** needed to type the word.

---

## Example 1

```text
Input: word = "abcde"

Output: 5
```

**Explanation**

Every letter appears once.

Assign each letter as the first letter on a different key.

```
1 + 1 + 1 + 1 + 1 = 5
```

---

## Example 2

```text
Input: word = "xyzxyzxyzxyz"

Output: 12
```

**Explanation**

Frequency:

```
x → 4
y → 4
z → 4
```

Assign each to the first position of different keys.

```
4×1 + 4×1 + 4×1 = 12
```

---

## Example 3

```text
Input: word = "aabbccddeeffgghhiiiiii"

Output: 24
```

# Intuition

Unlike **3014**, letters can appear multiple times.

A letter that appears many times contributes more to the total cost.

Therefore,

- **Most frequent letters should require fewer pushes.**
- Less frequent letters can be placed deeper inside the keys.

This is a classic **Greedy** strategy.

---

# Greedy Observation

Suppose two letters have frequencies:

```
a → 20
b → 2
```

If

```
a costs 2 pushes
b costs 1 push
```

Total cost

```
20×2 + 2×1 = 42
```

Swap them

```
a costs 1 push
b costs 2 pushes

20×1 + 2×2 = 24
```

Much smaller.

So,

> **Higher frequency letters must always receive smaller push counts.**

---

# Approach 1 (HashMap + Sorting)

### Idea

1. Count the frequency of every distinct letter.
2. Sort frequencies in descending order.
3. The first 8 frequencies cost **1 push**.
4. Next 8 cost **2 pushes**.
5. Continue similarly.

---

## Algorithm

1. Count frequencies using HashMap.
2. Store frequencies in a list.
3. Sort in descending order.
4. For every frequency

```
cost = (index / 8) + 1
```

5. Add

```
frequency × cost
```

---

## Java Solution

```java
class Solution {
    public int minimumPushes(String word) {

        Map<Character, Integer> map = new HashMap<>();

        for (char ch : word.toCharArray()) {
            map.put(ch, map.getOrDefault(ch, 0) + 1);
        }

        List<Integer> freq = new ArrayList<>(map.values());

        freq.sort(Collections.reverseOrder());

        int ans = 0;

        for (int i = 0; i < freq.size(); i++) {
            ans += freq.get(i) * (i / 8 + 1);
        }

        return ans;
    }
}
```

---

# Approach 2 (Counting Array + Sorting)

Instead of using a HashMap,

Since there are only **26 lowercase letters**, use a frequency array.

After counting,

- sort the array,
- traverse from largest frequency to smallest.

This avoids HashMap overhead.

---

## Algorithm

1. Create frequency array of size 26.
2. Count occurrences.
3. Sort the array.
4. Traverse from largest frequency.
5. Every 8 letters increase push count.

---

## Java Solution

```java
class Solution {
    public int minimumPushes(String word) {

        int[] freq = new int[26];

        for (int i = 0; i < word.length(); i++) {
            freq[word.charAt(i) - 'a']++;
        }

        Arrays.sort(freq);

        int ans = 0;
        int count = 0;

        for (int i = 25; i >= 0; i--) {
            int push = (count / 8) + 1;
            ans += push * freq[i];
            count++;
        }

        return ans;
    }
}
```

# Why Greedy Works

Suppose

```
freq(A) > freq(B)
```

If

```
cost(A) > cost(B)
```

Swapping their positions changes the total cost by

```
freq(A) × cost(B)
+ freq(B) × cost(A)

<
freq(A) × cost(A)
+ freq(B) × cost(B)
```

Therefore,

placing the higher-frequency letter at a lower push count always reduces (or maintains) the total cost.

Hence, sorting frequencies in descending order is always optimal.

## Approach 1

Overall

```
O(n)
```

- **Space:** `O(26)`

- **Time:** `O(n + 26 log 26)`

Since 26 is constant,

```
O(n)
```

- **Space:** `O(26)` → `O(1)`

# Difference Between 3014 and 3016

| 3014 | 3016 |
|-------|-------|
| Every letter is distinct | Letters can repeat |
| No frequencies needed | Frequency counting required |
| Fill groups of 8 directly | Sort frequencies first |
| Greedy by position | Greedy by frequency |

---

# Key Takeaways

- This is a **Greedy + Frequency Counting** problem.
- The most frequent letters should receive the smallest push counts.
- Every **8 letters** share the same push cost.
- Since only **26 letters** exist, both approaches run in **O(n)** time.
- The frequency-array solution is simpler and more efficient than using a HashMap.

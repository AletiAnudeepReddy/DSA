3302. Find the Lexicographically Smallest Valid Sequence

Difficulty: Medium
Topics: Greedy, String, Subsequence, Suffix Preprocessing

Intuition

We need to select exactly word2.length() indices from word1 such that:

Indices are strictly increasing.
The selected characters form a string that differs from word2 in at most one position.
Among all valid index arrays, we need the lexicographically smallest one.

The important part is condition 3.

For every position of word2, we want to choose the smallest possible index from word1.

But there is one special operation available:

We are allowed to use at most one mismatching character.

So when word1[i] != word2[j], we can potentially use i as the one changed character.

The question becomes:

If I use i as the mismatch, can the remaining suffix of word2 still be matched?

This is where the suff[] array helps.

Approach

We use two phases:

Phase 1: Build suff[]

suff[i] tells us:

How many characters of the remaining suffix of word2 can be matched as a subsequence inside word1[i...].

We calculate this greedily from right to left.

int[] suff = new int[n + 1];

int j = m - 1;
int matched = 0;

for (int i = n - 1; i >= 0; i--) {
    if (j >= 0 && s[i] == t[j]) {
        matched++;
        j--;
    }

    suff[i] = matched;
}

For example, if we need to match:

word2 = "abc"

and from some position in word1 we can match "bc", then:

suff[i] = 2
Phase 2: Greedily construct the answer

We scan word1 from left to right.

For each position:

Case 1: Characters match

If

word1[i] == word2[j]

we should immediately select i.

Why?

Because we are trying to make the index array lexicographically smallest.

So:

ans[j] = i;
j++;
Case 2: Characters don't match

Suppose:

word1[i] != word2[j]

We could use this index as our one allowed modification.

But we cannot blindly use it.

We need to check whether the remaining characters can still be matched.

After selecting i, we need:

m - j - 1

characters remaining.

So we check:

suff[i + 1] >= m - j - 1

If this is true, we can safely use i as our one mismatch.

ans[j] = i;
i++;
j++;
break;

Then the remaining positions must match normally.

Why is this Greedy?

Suppose we have two possible indices:

i < k

for the current character of word2.

If choosing i can still produce a valid answer, then choosing i is always better because the answer is compared lexicographically by indices.

For example:

[1, 5, 8]
[2, 4, 7]

The first array is smaller because:

1 < 2

We don't care that later indices might be larger.

Therefore:

Always choose the earliest possible index, provided the remaining suffix can still form a valid sequence.

The suff[] array lets us determine exactly that.

Example
word1 = "vbcca"
word2 = "abc"

Initially:

word1: v b c c a
        0 1 2 3 4

word2: a b c
        0 1 2

At index 0:

v != a

We can use index 0 as our one modification.

Remaining:

word2 = "bc"

The suffix of word1 can match "bc".

Therefore:

ans[0] = 0

Then we match:

b -> index 1
c -> index 2

Answer:

[0, 1, 2]
Why suff[i + 1]?

Suppose we use:

i

as the mismatch.

That means we have already used one character of word2.

So we need to match:

word2[j + 1 ... m-1]

using:

word1[i+1 ... n-1]

Therefore we check:

suff[i + 1] >= m - j - 1

This is the key condition of the solution.

Code
class Solution {

    public int[] validSequence(String word1, String word2) {

        char[] s = word1.toCharArray();
        char[] t = word2.toCharArray();

        int n = s.length;
        int m = t.length;

        // suff[i] = number of characters of word2
        // that can be matched in word1[i...n-1]
        int[] suff = new int[n + 1];

        int j = m - 1;
        int matched = 0;

        for (int i = n - 1; i >= 0; i--) {

            if (j >= 0 && s[i] == t[j]) {
                matched++;
                j--;
            }

            suff[i] = matched;
        }

        int[] ans = new int[m];

        int i = 0;
        j = 0;

        // Greedily construct the answer
        while (i < n && j < m) {

            // Characters already match
            if (s[i] == t[j]) {

                ans[j] = i;
                j++;

            } else {

                // Use this index as the one allowed mismatch
                if (suff[i + 1] >= m - j - 1) {

                    ans[j] = i;

                    i++;
                    j++;

                    break;
                }
            }

            i++;
        }

        // Not enough indices
        if (j < m && i == n) {
            return new int[0];
        }

        // Match the remaining characters normally
        while (i < n && j < m) {

            if (s[i] == t[j]) {
                ans[j] = i;
                j++;
            }

            i++;
        }

        if (j != m) {
            return new int[0];
        }

        return ans;
    }
}
Important Observation

There are actually two different subsequence problems happening:

Before the mismatch

We greedily choose indices that match:

word2[j]
At the mismatch

We are allowed to change one character, so we can select that index even though:

word1[i] != word2[j]

But only if the remaining suffix is possible.

After the mismatch

No more mismatches are allowed, so we simply find the remaining characters as a normal subsequence.

Complexity

Let:

n = word1.length()
m = word2.length()
Time

Building suff:

O(n)

Constructing the answer:

O(n)

Total:

O(n)
Space
suff[] = O(n)
ans[]  = O(m)

Total:

O(n + m)
Key Takeaways

This problem combines Greedy + Suffix Preprocessing.

The main idea to remember is:

Choose the smallest index possible
        ↓
If characters match → take it
        ↓
If they don't match → use the one allowed modification
        ↓
But only if the remaining suffix is still possible

The crucial check is:

suff[i + 1] >= m - j - 1

which means:

"After using i as my one mismatch, are there enough matching characters remaining to complete word2?"

This allows us to make the sequence lexicographically smallest while still guaranteeing that it is valid.

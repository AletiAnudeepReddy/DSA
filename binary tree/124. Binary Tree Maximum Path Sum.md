# 124. Binary Tree Maximum Path Sum

**Difficulty:** Hard  
**Topics:** Binary Tree, DFS, Recursion

---

# Problem Statement

A **path** in a binary tree is a sequence of connected nodes.

- The path **does not need to pass through the root**.
- A node can appear **only once** in the path.
- The path can start and end at **any node**.

Return the **maximum path sum** among all possible paths.

---

# Intuition

This problem is very similar to **Diameter of Binary Tree**.

In Diameter:

```
Diameter = Left Height + Right Height
```

Here,

instead of heights, we use **maximum path sums**.

For every node,

```
Maximum Path Through Node

=

Left Contribution

+

Root Value

+

Right Contribution
```

The answer is the maximum of this value over all nodes.

---

# Important Observation

The maximum path **does not always pass through the root**.

Example

```
        -10
        /  \
       9   20
          /  \
         15   7
```

Maximum path

```
15 → 20 → 7

=

42
```

It never includes `-10`.

Hence, we must compute the answer at **every node**.

---

# Why Ignore Negative Paths?

Suppose

```
      5
     /
   -10
```

Including `-10`

```
5 + (-10)

=

-5
```

is worse than simply taking

```
5
```

So,

whenever a subtree contributes a negative sum,

we simply ignore it.

This is why we write:

```java
leftSum = Math.max(0, leftSum);
rightSum = Math.max(0, rightSum);
```

Negative paths contribute **0**.

---

# Recursive Relation

For every node,

Compute the best contribution from the left subtree.

```
leftContribution

=

max(0, leftSum)
```

Compute the best contribution from the right subtree.

```
rightContribution

=

max(0, rightSum)
```

The maximum path **passing through** the current node is

```
leftContribution

+

root.val

+

rightContribution
```

Update the global answer.

Now return **only one side** upward.

```
root.val

+

max(leftContribution, rightContribution)
```

We cannot return both sides because the parent can continue the path in only one direction.

---

# Why Return Only One Side?

Consider

```
        10
       /
      5
     / \
    2   8
```

At node `5`

The best path through it is

```
2 → 5 → 8
```

But if the parent also wants to extend the path,

we cannot return

```
2 + 5 + 8
```

because that would create a branch.

A valid path cannot split into two directions when moving upward.

So we return only

```
5 + max(2,8)
```

# Algorithm

1. If the node is `null`, return `0`.
2. Compute the maximum contribution from the left subtree.
3. Compute the maximum contribution from the right subtree.
4. Ignore negative contributions using

```
max(0, contribution)
```

5. Update the global answer with

```
left + right + root.val
```

6. Return

```
root.val + max(left, right)
```

---

## Complexity

- **Time Complexity:** `O(n)`
- **Space Complexity:** `O(h)` *(recursion stack)*

Where

- `n` = Number of nodes
- `h` = Height of the tree

---

## Java Solution

```java
class Solution {

    public int maxPathSum(TreeNode root) {

        int[] maxValue = new int[1];
        maxValue[0] = Integer.MIN_VALUE;

        maxPath(root, maxValue);

        return maxValue[0];
    }

    private int maxPath(TreeNode root, int[] maxValue) {

        if (root == null) {
            return 0;
        }

        int leftSum = Math.max(0, maxPath(root.left, maxValue));
        int rightSum = Math.max(0, maxPath(root.right, maxValue));

        maxValue[0] = Math.max(maxValue[0],
                               leftSum + rightSum + root.val);

        return root.val + Math.max(leftSum, rightSum);
    }
}
```

# Key Takeaways

- The maximum path can start and end at **any node**.
- The path **does not need to pass through the root**.
- Ignore negative subtree sums using:

  ```java
  Math.max(0, subtreeSum)
  ```

- At every node:
  - Update the global answer using **left + root + right**.
  - Return **only one side** (`root + max(left, right)`) to the parent.
- Returning both sides upward would create an invalid branching path.
- This single DFS traversal gives the optimal **`O(n)`** solution.

### Memory Trick

```
Compute Left Contribution

↓

Compute Right Contribution

↓

Ignore Negative Contributions

↓

Update Global Answer

(left + root + right)

↓

Return

(root + max(left, right))
```

> **Relation to Diameter of Binary Tree (543):**
>
> - **Diameter:** `leftHeight + rightHeight`
> - **Maximum Path Sum:** `leftContribution + root.val + rightContribution`
>
> Both problems use the same DFS pattern of computing values bottom-up while maintaining a global answer.

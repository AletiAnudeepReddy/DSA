# 106. Construct Binary Tree from Inorder and Postorder Traversal

**Difficulty:** Medium  
**Topics:** Binary Tree, DFS, Recursion, HashMap

---

# Problem Statement

Given the **Inorder** and **Postorder** traversal of a binary tree, construct and return the original binary tree.

It is guaranteed that the tree can be uniquely reconstructed.

---

# Intuition

The solution is based on the properties of tree traversals.

### Inorder Traversal

```
Left → Root → Right
```

The root divides the tree into:

- Left Subtree
- Right Subtree

### Postorder Traversal

```
Left → Right → Root
```

The **last element** is always the **root** of the current subtree.

So at every recursive call:

1. Pick the last element of postorder as the root.
2. Find that root in inorder.
3. Elements to the left belong to the left subtree.
4. Elements to the right belong to the right subtree.
5. Repeat recursively.

---


```
        3
      /   \
 [9]     [15,20,7]
```

Left subtree contains

```

```

Using this size, we split the postorder array.

Left Postorder

```
[9]
```

Right Postorder

```
[15,7,20]
```

Then recursively build both subtrees.

# Why HashMap?

Searching for every root in inorder using a loop would take

```
O(n)
```

for every recursive call.

Instead, store

```
Value → Index
```

inside a HashMap.

Example

```
Inorder

[9,3,15,20,7]
```

Map

```
9  -> 0

3  -> 1

15 -> 2

20 -> 3

7  -> 4
```

Lookup becomes

```
O(1)
```

# How are the Recursive Ranges Calculated?

Suppose

```
Inorder

[9,3,15,20,7]

Postorder

[9,15,7,20,3]
```

Current root

```
3
```

Inorder index

```
1
```

Number of nodes in left subtree

```
numsLeft

=

inRoot - inStart

=

1 - 0

=

1
```

---

### Left Subtree

Inorder

```
inStart

to

inRoot - 1
```

Postorder

```
postStart

to

postStart + numsLeft - 1
```

---

### Right Subtree

Inorder

```
inRoot + 1

to

inEnd
```

Postorder

```
postStart + numsLeft

to

postEnd - 1
```

> **Why `postEnd - 1`?**  
> Because `postEnd` is the current root, so the right subtree ends just before it.

# Algorithm

1. Store inorder indices in a HashMap.
2. Pick the last element of postorder as the root.
3. Find its position in inorder.
4. Calculate the size of the left subtree.
5. Recursively construct:
   - Left subtree
   - Right subtree
6. Return the root.

---

## Complexity

- **Time Complexity:** `O(n)`
- **Space Complexity:** `O(n)`

Where:

- `n` = Number of nodes

---

## Java Solution

```java
class Solution {

    public TreeNode buildTree(int[] inorder, int[] postorder) {

        Map<Integer, Integer> inorderMap = new HashMap<>();

        for (int i = 0; i < inorder.length; i++) {
            inorderMap.put(inorder[i], i);
        }

        return build(inorder, 0, inorder.length - 1,
                     postorder, 0, postorder.length - 1,
                     inorderMap);
    }

    private TreeNode build(int[] inorder,
                           int inStart,
                           int inEnd,
                           int[] postorder,
                           int postStart,
                           int postEnd,
                           Map<Integer, Integer> inorderMap) {

        if (inStart > inEnd || postStart > postEnd) {
            return null;
        }

        TreeNode root = new TreeNode(postorder[postEnd]);

        int inRoot = inorderMap.get(root.val);

        int numsLeft = inRoot - inStart;

        root.left = build(inorder,
                          inStart,
                          inRoot - 1,
                          postorder,
                          postStart,
                          postStart + numsLeft - 1,
                          inorderMap);

        root.right = build(inorder,
                           inRoot + 1,
                           inEnd,
                           postorder,
                           postStart + numsLeft,
                           postEnd - 1,
                           inorderMap);

        return root;
    }
}
```

# Key Takeaways

- **Postorder** always gives the **root** as the **last element**.
- **Inorder** splits the tree into left and right subtrees.
- A **HashMap** provides `O(1)` lookup for root positions.
- Left subtree size determines how the postorder array is split.
- Every node is processed once, giving **`O(n)`** time complexity.

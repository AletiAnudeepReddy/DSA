3702. Longest Subsequence With Non-Zero Bitwise XOR
🧩 Problem

Given an integer array nums, find the maximum length subsequence whose bitwise XOR is not zero.

If there is no subsequence with non-zero XOR, return 0.

Example 1
Input:  nums = [1, 2, 3]
Output: 2

The XOR of the entire array is:

1 ^ 2 ^ 3 = 0

So we cannot take all 3 elements.

But:

2 ^ 3 = 1

which is non-zero.

Therefore:

Answer = 2
Example 2
Input: nums = [2, 3, 4]
2 ^ 3 ^ 4 = 5

Since the XOR of the entire array is already non-zero:

Answer = 3
💡 Key Observation

The entire problem can be solved by looking at the XOR of all elements.

Let:

xor = nums[0] ^ nums[1] ^ ... ^ nums[n-1]

There are only two important cases.

Case 1: Total XOR is non-zero

Example:

nums = [2,3,4]


2 ^ 3 ^ 4 = 5

Since the entire array is a subsequence and its XOR is non-zero:

Answer = n

We cannot do better than taking all n elements.

Case 2: Total XOR is zero

Example:

nums = [1,2,3]
1 ^ 2 ^ 3 = 0

So the entire array cannot be used.

Can we simply remove one element and get a non-zero XOR?

Suppose we remove x.

The XOR of the remaining elements becomes:

totalXOR ^ x

Since:

totalXOR = 0

we get:

0 ^ x = x

Therefore, if we remove any non-zero element, the remaining XOR becomes non-zero.

So:

Answer = n - 1

provided there is at least one non-zero element.

❗ Special Case: All Elements Are Zero

Example:

nums = [0,0,0]

Any subsequence consists only of zeroes.

Therefore:

0 ^ 0 ^ 0 = 0

There is no subsequence whose XOR is non-zero.

So:

Answer = 0
🧠 Final Logic

We only need three things:

Calculate XOR of the entire array.
Count whether all elements are zero.
Decide based on the total XOR.
                  Total XOR
                     |
              +------+------+
              |             |
            != 0            = 0
              |             |
            answer       All elements
              n             zero?
                            /    \
                          YES     NO
                           |       |
                         answer   answer
                           0       n-1
✅ Optimized Solution
class Solution {


    public int longestSubsequence(int[] nums) {


        int n = nums.length;


        int xor = 0;
        int zeros = 0;


        for (int x : nums) {


            if (x == 0) {
                zeros++;
            }


            xor ^= x;
        }


        // Every element is zero
        if (zeros == n) {
            return 0;
        }


        // Entire array has non-zero XOR
        if (xor != 0) {
            return n;
        }


        // Entire XOR is zero, but at least one
        // non-zero element exists.
        return n - 1;
    }
}

🧠 Why Does Removing One Element Work?

This is the main mathematical trick in this problem.

Suppose:

a ^ b ^ c ^ d = 0

Remove c.

The XOR of the remaining elements is:

a ^ b ^ d

We know:

a ^ b ^ c ^ d = 0

XOR both sides with c:

(a ^ b ^ c ^ d) ^ c = 0 ^ c

Because:

c ^ c = 0

we get:

a ^ b ^ d = c

Therefore, if c != 0, the remaining elements have a non-zero XOR.

That means whenever:

total XOR = 0

and there is at least one non-zero element, removing that one element gives us a valid subsequence of length:

n - 1

And because the entire array has length n but is invalid, n - 1 is necessarily optimal.

🔄 Your Recursive Approach

You also wrote a recursive solution:

class Solution {


    public int recur(int[] nums, int i, int x) {


        if (i == nums.length) {
            return x != 0 ? 0 : Integer.MIN_VALUE;
        }


        int take = recur(nums, i + 1, x ^ nums[i]);


        if (take != Integer.MIN_VALUE) {
            take++;
        }


        int nottake = recur(nums, i + 1, x);


        return Math.max(take, nottake);
    }


    public int longestSubsequence(int[] nums) {
        return recur(nums, 0, 0);
    }
}

The idea is correct.

At every element, we have two choices:

             nums[i]
             /     \
          TAKE    NOT TAKE
            |        |
        x ^ nums[i]  x

At the end:

x != 0

means we found a valid subsequence.

Otherwise:

Integer.MIN_VALUE

represents an invalid subsequence.

⚠️ Why Recursion Is Too Slow

For every element we have two choices:

take
not take

Therefore, the recursion creates approximately:

2^n

possibilities.

For:

n = 100000

this is completely impossible.

Complexity
Time:  O(2^n)
Space: O(n)

The O(n) space is the recursion stack.

So although the recursive solution helps us understand the problem, it should not be used for the given constraints.

🚀 Optimized Approach

We don't actually need to consider every subsequence.

We only need:

1. XOR of the entire array
2. Whether at least one element is non-zero

Therefore we can solve the problem in one pass.

Complexity
Time:  O(n)
Space: O(1)

This is optimal because we have to inspect the elements at least once.

📌 Important XOR Properties

Remember these properties:

1. XOR with zero
x ^ 0 = x
2. XOR with itself
x ^ x = 0
3. XOR is reversible
a ^ b = c


c ^ b = a
4. Order doesn't matter
a ^ b ^ c
=
c ^ a ^ b

These properties are what make the n vs n-1 observation work.

⭐ Final Takeaway

The entire problem reduces to:

if all elements are 0:
    return 0


calculate total XOR


if total XOR != 0:
    return n


otherwise:
    return n - 1
One-line intuition

If the XOR of the whole array is non-zero, take everything; if it is zero, remove one non-zero element; if there is no non-zero element, no valid subsequence exists.

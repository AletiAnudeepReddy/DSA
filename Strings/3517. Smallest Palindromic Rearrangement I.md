# 3517. Smallest Palindromic Rearrangement I

**Difficulty:** Medium  
**Topic:** Greedy, Counting, String

## Problem Statement

You are given a **palindromic string** `s`.

Return the **lexicographically smallest palindromic permutation** of `s`.

A palindrome reads the same forwards and backwards.

---

### Example 1

**Input**

```text
s = "z"
```

**Output**

```text
"z"
```

**Explanation**

A single character is already the smallest possible palindrome.

---

### Example 2

**Input**

```text
s = "abba"
```

**Output**

```text
"abba"
```

---

### Example 3

**Input**

```text
s = "cbbc"
```

**Output**

```text
"bccb"
```

---

# Intuition

Since the given string is **already a palindrome**, the second half is simply the mirror image of the first half.

Therefore, we only need to consider the **first half** of the string.

For the lexicographically smallest palindrome:

- Arrange the first half in **sorted order**.
- Keep the middle character unchanged (only for odd length).
- Mirror the sorted first half to form the second half.

This guarantees the smallest possible palindrome.

---

# Key Observation

Suppose

```text
s = "dcabbacd"
```

First half:

```text
dcab
```

Character frequencies:

```text
a -> 1
b -> 1
c -> 1
d -> 1
```

Sort the first half:

```text
abcd
```

Mirror it:

```text
dcba
```

Final palindrome:

```text
abcddcba
```

This is the smallest possible palindromic rearrangement.

---

# Algorithm

1. Count the frequency of characters in the **first half** of the string.
2. Build the first half in sorted order (`a` to `z`).
3. If the string length is odd, keep the middle character.
4. Reverse the first half to obtain the second half.
5. Concatenate:

```text
firstHalf + middle + reverse(firstHalf)
```

---

# Java Code

```java
class Solution {

    public String smallestPalindrome(String s) {

        int[] freq = new int[26];
        int n = s.length();

        for (int i = 0; i < n / 2; i++) {
            freq[s.charAt(i) - 'a']++;
        }

        StringBuilder firstHalf = new StringBuilder();

        for (int i = 0; i < 26; i++) {
            while (freq[i]-- > 0) {
                firstHalf.append((char) (i + 'a'));
            }
        }

        StringBuilder ans = new StringBuilder();

        ans.append(firstHalf);

        if (n % 2 == 1) {
            ans.append(s.charAt(n / 2));
        }

        ans.append(new StringBuilder(firstHalf).reverse());

        return ans.toString();
    }
}
```

# Why Does This Work?

The second half of every palindrome is completely determined by the first half.

To obtain the **lexicographically smallest palindrome**, we only need to make the first half as small as possible.

Sorting the first half in ascending order guarantees the smallest lexicographical order, while mirroring preserves the palindrome property.

---

# Complexity Analysis

- **Time Complexity:** O(n)
- **Space Complexity:** O(1)

(Only a frequency array of size 26 is used.)

---

# Key Takeaways

- Since the input is already a palindrome, only the **first half** needs to be processed.
- Count characters from the first half only.
- Sort the first half greedily.
- Keep the middle character unchanged (for odd-length strings).
- Mirror the sorted first half to construct the smallest palindrome.
- This is a **Greedy + Counting** problem.

# Alternative Implementation

The same idea can be implemented more concisely:

```java
class Solution {

    public String smallestPalindrome(String s) {

        int[] freq = new int[26];
        int n = s.length();

        String middle = (n % 2 == 0) ? "" : String.valueOf(s.charAt(n >> 1));

        n >>= 1;

        for (int i = 0; i < n; i++) {
            freq[s.charAt(i) - 'a']++;
        }

        StringBuilder firstHalf = new StringBuilder();

        for (int i = 0; i < 26; i++) {
            firstHalf.append(
                String.valueOf((char)(i + 'a')).repeat(freq[i])
            );
        }

        return firstHalf.toString()
                + middle
                + firstHalf.reverse().toString();
    }
}
```

Both implementations use the same greedy strategy and have identical time and space complexity.

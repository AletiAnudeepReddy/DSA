# 173. Binary Search Tree Iterator

**Difficulty:** Medium  
**Topic:** Binary Search Tree, Stack, Iterator, Design

---

## Problem Statement

Implement a **BST Iterator** that iterates over the **inorder traversal** of a Binary Search Tree (BST).

The iterator should support the following operations:

- **BSTIterator(TreeNode root)** → Initializes the iterator.
- **next()** → Returns the next smallest element.
- **hasNext()** → Returns `true` if another element exists.

The iterator should behave like an inorder traversal performed one node at a time.

---

## Approach: Stack (Lazy Inorder Traversal)

### Intuition

Recall that an **inorder traversal** visits nodes in the order:

```
Left → Root → Right
```

For a BST, inorder traversal naturally produces the values in **ascending order**.

Instead of storing the entire inorder traversal in an array, we simulate the traversal **on demand** using a stack.

The idea is:

- Initially push **all left nodes** starting from the root.
- The top of the stack is always the next smallest element.
- After removing a node, if it has a right child, push all the left descendants of its right subtree.

This way, the stack always contains the path to the next smallest element.

---

## Why does this work?

Suppose the BST is:

```
        7
       / \
      3   15
         /  \
        9   20
```

Initially we push all left nodes.

```
Stack

Top
3
7
```

The smallest element (`3`) is on the top.

---

When `next()` is called:

```
Pop 3

Stack

7
```

Since `3` has no right child, nothing more is pushed.

The next smallest element is now `7`.

---

When `next()` is called again:

```
Pop 7
```

Now we process its right subtree.

Push all left nodes from `15`.

```
Push 15
Push 9

Stack

Top
9
15
```

Again, the smallest remaining element (`9`) is on top.

This process continues until all nodes are visited.

---

## Algorithm

### Constructor

- Push all left descendants starting from the root.

### next()

1. Pop the top node.
2. If it has a right child:
   - Push the right child and all of its left descendants.
3. Return the popped node's value.

### hasNext()

Return whether the stack is empty.

---

## Code (Java)

```java
class BSTIterator {

    Stack<TreeNode> stk = new Stack<>();

    public BSTIterator(TreeNode root) {
        pushAll(root);
    }

    public int next() {

        TreeNode node = stk.pop();

        pushAll(node.right);

        return node.val;
    }

    public boolean hasNext() {
        return !stk.isEmpty();
    }

    private void pushAll(TreeNode root) {

        while (root != null) {
            stk.push(root);
            root = root.left;
        }
    }
}
```

## Complexity Analysis

### Constructor

In the worst case, we push all left nodes.

- **Time:** `O(h)`
- **Space:** `O(h)`

where `h` is the height of the tree.

---

### next()

Each node is:

- pushed exactly once
- popped exactly once

Therefore,

- **Worst-case Time:** `O(h)`
- **Amortized Time:** `O(1)`

---

### hasNext()

- **Time:** `O(1)`
- **Space:** `O(1)`

---

# Why is the amortized complexity O(1)?

Although a single `next()` may push several nodes,

every node in the tree is:

- pushed **once**
- popped **once**

For a tree with `n` nodes,

- Total pushes = `n`
- Total pops = `n`

Total work:

```
2n
```

spread across `n` calls to `next()`.

Hence,

```
Average (Amortized) Time

= O(1)
```

---

# Key Takeaway

Instead of storing the complete inorder traversal, we perform a **lazy inorder traversal** using a stack.

The stack always stores the path to the next smallest element.

This achieves:

- **Constructor:** `O(h)`
- **next():** `O(1)` amortized
- **hasNext():** `O(1)`
- **Space:** `O(h)`

making it the optimal solution for implementing a BST iterator.

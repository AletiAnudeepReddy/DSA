# 230. Kth Smallest Element in a BST

**Difficulty:** Medium  
**Topic:** Binary Search Tree (BST), Inorder Traversal

---

## Intuition

A Binary Search Tree (BST) has a special property:

- Left subtree contains smaller values.
- Root contains the next greater value.
- Right subtree contains larger values.

Therefore, an **Inorder Traversal (Left → Root → Right)** of a BST always visits the nodes in **ascending order**.

So,

- 1st node visited → 1st smallest
- 2nd node visited → 2nd smallest
- ...
- kth node visited → kth smallest

We simply perform an inorder traversal and count the visited nodes.

---

## Approach

- Traverse the tree using inorder traversal.
- Maintain a counter for the number of nodes visited.
- Whenever a node is visited:
  - Increment the counter.
  - If `count == k`, store the answer.
- Return the stored result.

---

## Algorithm

1. Initialize:
   - `count = 0`
   - `result = -1`
2. Perform inorder traversal.
3. Visit nodes in ascending order.
4. Increment `count`.
5. When `count == k`, store the node value.
6. Return `result`.

---

## Code (Java)

```java
class Solution {

    private int count = 0;
    private int result = -1;

    public int kthSmallest(TreeNode root, int k) {
        inorder(root, k);
        return result;
    }

    private void inorder(TreeNode root, int k) {

        if (root == null) {
            return;
        }

        inorder(root.left, k);

        count++;

        if (count == k) {
            result = root.val;
            return;
        }

        inorder(root.right, k);
    }
}
```

## Dry Run

BST

```
        5
       / \
      3   7
     / \   \
    2   4   8
```

Suppose `k = 3`

### Inorder Traversal

```
2 → 3 → 4 → 5 → 7 → 8
```

Visit order

|Visited Node|Count|
|------------|-----|
|2|1|
|3|2|
|4|3 ✅|

Answer = **4**

---

## Complexity Analysis

- **Time Complexity:** `O(H + k)`
  - `H` = Height of the tree.
  - We traverse until the kth node is found.
  - Worst case: `O(n)`.

- **Space Complexity:** `O(H)`
  - Recursive call stack.

---

## Kth Largest Element

For the kth largest element, there are **two approaches**.

### Approach 1 (Using Kth Smallest)

If the tree has `n` nodes,

```
kth Largest = (n - k + 1)th Smallest
```

Example:

```
Sorted Order:
1 2 3 4 5 6 7

k = 2

2nd Largest = 6

n = 7

(n - k + 1) = 7 - 2 + 1 = 6

6th Smallest = 6
```

So,

```
Kth Largest = (n - k + 1)th Smallest
```

---

### Approach 2 (Reverse Inorder)

Since inorder gives ascending order,

Reverse Inorder

```
Right → Root → Left
```

visits nodes in **descending order**.

```
8 → 7 → 5 → 4 → 3 → 2
```

The kth visited node will be the **kth largest**.

This is usually the preferred approach because it avoids counting the total number of nodes first.

---

## Key Takeaways

- Inorder traversal of a BST always produces **sorted order**.
- Count nodes during inorder traversal to find the kth smallest element.
- **Kth Largest = (n - k + 1)th Smallest**, where `n` is the total number of nodes.
- Alternatively, perform a **Reverse Inorder Traversal (Right → Root → Left)** to directly find the kth largest.

# 3310. Remove Methods From Project

**Difficulty:** Medium  
**Topics:** Graph, BFS, DFS, Topological Sort

---

## Intuition

Method `k` contains a bug.

Any method that is **directly or indirectly invoked** by `k` also becomes **suspicious**.

However, we are allowed to remove the suspicious methods **only if no non-suspicious method invokes any suspicious method**.

So the problem has two parts:

1. Find every suspicious method.
2. Check whether any edge comes from a safe method into a suspicious method.

If such an edge exists, removal is impossible, so we return every method.

---

## Approach

### Step 1: Build the graph

Create an adjacency list.

```
a -> b
```

means

```
method a invokes method b
```

Also compute the indegree of every node.

---

### Step 2: Find all suspicious methods

Start BFS from method `k`.

Every reachable node becomes suspicious.

During traversal, decrease the indegree of every visited neighbor.

```java
ind[neighbor]--;
```

After removing all edges coming from suspicious methods:

- If a suspicious node still has indegree > 0,
- then some safe method still invokes it.

Hence removal is impossible.

---

### Step 3: Validate removal

Traverse every node.

If

```
suspicious && indegree > 0
```

then

```
return all methods
```

Otherwise collect all non-suspicious methods.

---

## Algorithm

1. Build adjacency list.
2. Compute indegree of every node.
3. BFS from `k`.
4. Mark every reachable node as suspicious.
5. Remove outgoing edges by decrementing indegrees.
6. Traverse all nodes.
   - If a suspicious node still has indegree > 0 → cannot remove.
   - Otherwise collect remaining methods.
7. Return answer.

## Why does indegree work?

Initially,

```
indegree[node]
```

counts every incoming invocation.

During BFS, every suspicious method is assumed to be removed.

So we remove all outgoing edges from suspicious methods by decrementing indegree.

After this,

```
indegree[node]
```

only represents incoming edges from **non-suspicious methods**.

Therefore,

```
indegree > 0
```

means

```
Some safe method still invokes this suspicious method.
```

Hence the suspicious group cannot be removed.

---

## Correctness Proof

Let **S** be the set of suspicious methods found by BFS.

BFS visits every node reachable from `k`, so every directly or indirectly invoked method is included in `S`.

While processing every suspicious node, we remove all outgoing edges from `S`.

Therefore, after BFS:

- `indegree[x]` equals the number of incoming edges from nodes outside `S`.

If any suspicious node still has positive indegree, then a safe method invokes it.

Removing `S` would leave a dangling invocation, which violates the condition.

Otherwise, every invocation into `S` originates from another suspicious node, so removing the whole group is valid.

Thus the algorithm always returns exactly the correct answer.

## Java Solution

```java
class Solution {
    public List<Integer> remainingMethods(int n, int k, int[][] invocations) {

        List<Integer>[] edges = new ArrayList[n];
        for (int i = 0; i < n; i++) {
            edges[i] = new ArrayList<>();
        }

        int[] ind = new int[n];

        for (int[] in : invocations) {
            edges[in[0]].add(in[1]);
            ind[in[1]]++;
        }

        Queue<Integer> q = new ArrayDeque<>();

        q.offer(k);

        boolean[] sus = new boolean[n];
        sus[k] = true;

        while (!q.isEmpty()) {

            int node = q.poll();

            for (int next : edges[node]) {

                ind[next]--;

                if (!sus[next]) {
                    sus[next] = true;
                    q.offer(next);
                }
            }
        }

        boolean canRemove = true;

        List<Integer> remaining = new ArrayList<>();

        for (int i = 0; i < n; i++) {

            if (sus[i] && ind[i] > 0) {
                canRemove = false;
                break;
            }

            if (!sus[i]) {
                remaining.add(i);
            }
        }

        if (!canRemove) {
            List<Integer> all = new ArrayList<>();

            for (int i = 0; i < n; i++) {
                all.add(i);
            }

            return all;
        }

        return remaining;
    }
}
```

## Key Takeaways

- Reachability from `k` identifies all suspicious methods.
- Decreasing indegrees during BFS effectively removes edges originating from suspicious methods.
- Any suspicious node with remaining indegree has an incoming edge from a safe method, making removal invalid.
- This is a neat combination of **Graph Traversal (BFS/DFS)** and **Indegree (Topological Sort idea)**.

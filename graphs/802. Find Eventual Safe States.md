802. Find Eventual Safe States
Problem

You are given a directed graph where graph[i] contains all nodes that node i points to.

A node is called:

Terminal node → has no outgoing edges.
Safe node → every possible path starting from that node eventually reaches a terminal node.

Return all safe nodes in ascending order.

Example
graph = [[1,2],[2,3],[5],[0],[5],[],[]]

Output = [2,4,5,6]
5 and 6 are terminal → safe.
2 -> 5 → safe.
4 -> 5 → safe.
0, 1, 3 are involved in a cycle → unsafe.
Approach: Kahn's Algorithm + Reverse Graph

The important observation is:

A node is safe if all the nodes it points to are safe.

Step 1: Reverse the graph

Suppose we have:

0 -> 1
0 -> 2
2 -> 5

The reverse graph becomes:

1 -> 0
2 -> 0
5 -> 2

We do this because when a node becomes known to be safe, we want to find the nodes that were pointing towards it.

Step 2: Calculate indegree

Here, indegree[i] means:

How many outgoing edges does node i still have towards nodes that are not yet known to be safe?

Initially:

indegree[i] = graph[i].length;

Terminal nodes have:

indegree = 0

Therefore, all terminal nodes are our starting points.

Step 3: Put terminal nodes into the queue

For example:

5 -> []
6 -> []

So:

queue = [5, 6]

Both are immediately safe.

Step 4: Process the reverse graph

Suppose we remove safe node 5.

In the reverse graph:

5 -> 2

This means:

2 -> 5

Since 2 points to a safe node, decrease:

indegree[2]--

If indegree[2] becomes 0, all destinations of 2 are safe, so 2 is also safe.

This process continues.

Why does this detect cycles?

Consider:

0 -> 1
1 -> 2
2 -> 0

Every node has an outgoing edge.

Therefore:

indegree[0] = 1
indegree[1] = 1
indegree[2] = 1

None can become 0.

So none of them enters the queue → they are not safe.

This is exactly the same idea behind Kahn's Topological Sort.

Code
class Solution {

    public List<Integer> eventualSafeNodes(int[][] graph) {

        int V = graph.length;

        // Reverse graph
        List<List<Integer>> adjRev = new ArrayList<>();

        for (int i = 0; i < V; i++) {
            adjRev.add(new ArrayList<>());
        }

        // indegree[i] = number of outgoing edges from i
        int[] indegree = new int[V];

        for (int i = 0; i < V; i++) {

            for (int it : graph[i]) {

                // Original:
                // i -> it

                // Reverse:
                // it -> i
                adjRev.get(it).add(i);

                indegree[i]++;
            }
        }

        Queue<Integer> q = new LinkedList<>();

        // Terminal nodes
        for (int i = 0; i < V; i++) {
            if (indegree[i] == 0) {
                q.add(i);
            }
        }

        List<Integer> safeNodes = new ArrayList<>();

        // Kahn's algorithm
        while (!q.isEmpty()) {

            int node = q.poll();

            safeNodes.add(node);

            // Find nodes that point to this safe node
            for (int it : adjRev.get(node)) {

                indegree[it]--;

                if (indegree[it] == 0) {
                    q.add(it);
                }
            }
        }

        // Required in ascending order
        Collections.sort(safeNodes);

        return safeNodes;
    }
}

Important Intuition

This problem is essentially Kahn's algorithm in reverse.

Normal topological sort:

Start with nodes having indegree = 0
        ↓
Remove them
        ↓
Reduce indegree of their neighbors

For Eventual Safe States:

Start with nodes having OUTDEGREE = 0
        ↓
Reverse the graph
        ↓
Reduce the remaining OUTDEGREE
        ↓
When it becomes 0 → node is safe

So remember:

Terminal nodes are the starting points. Reverse the edges, then apply Kahn's algorithm.

Complexity

Let:

V = number of vertices
E = number of edges
Time Complexity

Building the reverse graph:

O(V + E)

Kahn's BFS:

O(V + E)

Sorting the answer:

O(V log V)

Therefore:

O(V + E + V log V)

Since LeetCode requires ascending order and the nodes are numbered 0...V-1, we can also avoid sorting by using a boolean array and scanning from 0 to V-1, giving:

O(V + E)
Space Complexity

Reverse adjacency list:

O(V + E)

Arrays + queue:

O(V)

Overall:

O(V + E)
Pattern to Remember

This is an important graph pattern:

Directed Graph
      ↓
Want nodes that eventually reach terminal nodes
      ↓
Start from terminal nodes
      ↓
Reverse edges
      ↓
Kahn's Algorithm
      ↓
Eventual Safe Nodes

Key idea:
If all the nodes that u points to are safe, then u is safe.

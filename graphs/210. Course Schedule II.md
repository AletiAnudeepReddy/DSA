210. Course Schedule II
Problem

You are given numCourses courses numbered from 0 to numCourses - 1.

prerequisites[i] = [a, b] means:

To take course a, you must first complete course b.

You need to return a valid ordering of all courses.

If it is impossible to finish all courses because of a cycle, return an empty array.

Example
numCourses = 4
prerequisites = [[1,0],[2,0],[3,1],[3,2]]

The dependencies are:

0 → 1
0 → 2
1 → 3
2 → 3

A valid ordering is:

[0, 2, 1, 3]

because:

0 comes before 1
0 comes before 2
1 comes before 3
2 comes before 3
Approach: Topological Sort using Kahn's Algorithm

This is a direct application of Topological Sort.

Important observation

If:

[1, 0]

then 0 must be completed before 1.

Therefore, we create the directed edge:

0 → 1

The graph becomes:

prerequisite → course
Step 1: Build the graph

For every:

[a, b]

add:

b → a

So:

adj.get(prerequisites[i][1]).add(prerequisites[i][0]);
Step 2: Calculate indegree

indegree[x] tells us:

How many prerequisites are still required before we can take course x?

For:

0 → 1
0 → 2
1 → 3
2 → 3

we get:

course:    0  1  2  3
indegree:  0  1  1  2

Course 0 has indegree 0, so we can take it immediately.

Step 3: Put all indegree-0 courses into the queue
for (int i = 0; i < V; i++) {
    if (indegree[i] == 0) {
        q.add(i);
    }
}

Initially:

Queue = [0]
Step 4: Process the queue

Take a course from the queue.

Suppose we take 0.

Then:

0 → 1
0 → 2

Taking course 0 satisfies one prerequisite for both 1 and 2.

Therefore:

indegree[1]--
indegree[2]--

Now:

indegree[1] = 0
indegree[2] = 0

So both can be added to the queue.

Continue this process until the queue becomes empty.

Detecting a Cycle

This is the important part.

Suppose:

0 → 1
1 → 0

Then:

indegree[0] = 1
indegree[1] = 1

There is no course with indegree 0.

Therefore, the queue is empty immediately and we cannot process all courses.

We use:

if (i == V)
    return topo;
else
    return new int[0];

If we processed fewer than V courses, a cycle exists.

Code
class Solution {

    public int[] findOrder(int V, int[][] prerequisites) {

        // Build adjacency list
        ArrayList<ArrayList<Integer>> adj = new ArrayList<>();

        for (int i = 0; i < V; i++) {
            adj.add(new ArrayList<>());
        }

        // [course, prerequisite]
        // prerequisite -> course
        for (int i = 0; i < prerequisites.length; i++) {
            adj.get(prerequisites[i][1])
               .add(prerequisites[i][0]);
        }

        // Calculate indegree
        int[] indegree = new int[V];

        for (int i = 0; i < V; i++) {
            for (int it : adj.get(i)) {
                indegree[it]++;
            }
        }

        // Add all courses with no prerequisites
        Queue<Integer> q = new LinkedList<>();

        for (int i = 0; i < V; i++) {
            if (indegree[i] == 0) {
                q.add(i);
            }
        }

        // Store topological ordering
        int[] topo = new int[V];
        int i = 0;

        while (!q.isEmpty()) {

            int node = q.poll();

            topo[i++] = node;

            // Remove this course's dependency
            for (int it : adj.get(node)) {

                indegree[it]--;

                if (indegree[it] == 0) {
                    q.add(it);
                }
            }
        }

        // If all courses were processed,
        // valid topological ordering exists.
        return i == V ? topo : new int[0];
    }
}

Why Does Kahn's Algorithm Work?

The key idea is:

A course with indegree = 0 has no remaining prerequisites, so it can safely be taken.

After taking that course, we remove its outgoing edges.

If another course now has:

indegree = 0

that course is also ready.

This continues until all courses are processed.

If some courses remain unprocessed, they must be involved in a cycle.

For example:

0 → 1 → 2 → 0

Every node always has an incoming edge.

Therefore, none of them can reach indegree 0.

Complexity

Let:

V = number of courses
E = number of prerequisite relationships
Time Complexity
O(V + E)

Why?

Building adjacency list → O(E)
Calculating indegrees → O(V + E)
BFS/topological sort → O(V + E)

Overall:

O(V + E)
Space Complexity
O(V + E)

Because we store:

adjacency list → O(V + E)
indegree array → O(V)
queue → O(V)
result array → O(V)
Connection With Course Schedule I

This problem is almost the same as 207. Course Schedule.

Course Schedule I

Only asks:

Can we finish all courses?

So after Kahn's algorithm:

return count == V;
Course Schedule II

Asks:

What is the valid order?

So we store every processed node:

topo[i++] = node;

and return the topological ordering.

The fundamental algorithm is the same:

Course Schedule I
        ↓

        ↓
Check whether count == V


Course Schedule II
        ↓

        ↓

Key Pattern to Remember

Whenever you see:

Prerequisites / dependencies / tasks that must be completed before other tasks

think:

DIRECTED GRAPH
      ↓
TOPOLOGICAL SORT
      ↓
KAHN'S ALGORITHM (BFS)

And remember the edge direction:

[course, prerequisite]

prerequisite → course

This direction is especially important in Course Schedule problems.

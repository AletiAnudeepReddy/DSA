2996. Smallest Missing Integer Greater Than Sequential Prefix Sum
Problem

Given an array nums, find the longest sequential prefix.

A prefix is sequential if every element after the first is exactly 1 greater than the previous element:

nums[i] = nums[i - 1] + 1

After finding this prefix:

Calculate its sum.
Starting from that sum, find the smallest integer that does not exist in nums.
Example
nums = [1,2,3,2,5]

The longest sequential prefix is:

[1,2,3]

Its sum is:

1 + 2 + 3 = 6

6 is not present, so:

answer = 6
Approach — Sequential Prefix + Hashing

There are two separate things we need to do:

Step 1: Find the longest sequential prefix

Start with:

sum = nums[0];

Then check whether:

nums[i] == nums[i - 1] + 1

If yes, the sequential prefix continues.

sum += nums[i];

Once this condition fails, the sequential prefix ends.

Step 2: Find the smallest missing integer

We need the smallest missing number:

>= sum

So we store all numbers in a boolean array:

seen[num] = true;

Then start checking from sum:

for (int i = sum; i < 52; i++) {
    if (!seen[i]) {
        return i;
    }
}

The first unseen value is our answer.

Code
class Solution {
    public int missingInteger(int[] nums) {

        int sum = nums[0];

        boolean[] seen = new boolean[52];
        seen[nums[0]] = true;

        boolean seq = true;

        for (int i = 1; i < nums.length; i++) {

            // Extend the sequential prefix
            if (seq && nums[i] == nums[i - 1] + 1) {
                sum += nums[i];
            } else {
                seq = false;

                // If sum is already greater than
                // every possible array value,
                // sum itself must be missing.
                if (sum > 50) {
                    return sum;
                }
            }

            seen[nums[i]] = true;
        }

        // Find the smallest missing integer >= sum
        for (int i = sum; i < 52; i++) {
            if (!seen[i]) {
                return i;
            }
        }

        return sum;
    }
}
Why seq Is Needed

Consider:

nums = [3,4,5,1,12,14,13]

Initially:

sum = 3
seq = true
4
4 == 3 + 1

So:

sum = 3 + 4 = 7
5
5 == 4 + 1

So:

sum = 7 + 5 = 12
1
1 != 5 + 1

The sequential prefix ends.

seq = false

We must not start another sequential prefix.

The problem specifically asks for the prefix starting from nums[0].

Therefore, after the first break, we only continue recording elements in seen.

Dry Run
nums = [3,4,5,1,12,14,13]
Finding the prefix
3
↓
4  -> sequential
↓
5  -> sequential
↓
1  -> break

So:

longest sequential prefix = [3,4,5]
sum = 12

The array contains:

1, 3, 4, 5, 12, 13, 14

Now start from 12:

12 -> exists
13 -> exists
14 -> exists
15 -> missing

Therefore:

answer = 15
Important Optimization

Your code has this:

if (sum > 50) {
    return sum;
}

Why is this valid?

From the constraints, the values in nums are small enough that the boolean array covers all possible values.

Once:

sum > maximum possible value in nums

there is no way sum can exist in the array.

Therefore:

sum

itself is the smallest missing integer.

This avoids needing a larger search range.

Why Start Searching From sum?

The problem says:

Find the smallest missing integer greater than or equal to the sequential prefix sum.

So we cannot search from 0.

For:

sum = 12

we only care about:

12, 13, 14, 15, ...

For example, if:

nums = [3,4,5,1,12,13,14]

then:

sum = 12

and:

12 exists
13 exists
14 exists
15 does not exist

Answer:

15
Why Boolean Array?

Instead of repeatedly doing:

for (...) {
    for (...) {
        ...
    }
}

we can directly mark whether a number exists.

seen[num] = true;

Then:

if (!seen[x])

immediately tells us whether x is missing.

This is essentially a frequency/presence array.

Complexity

Let n = nums.length.

Time

We traverse the array once:

O(n)

Then we perform a small bounded search for the missing value.

Overall:

O(n)
Space

The boolean array has constant size:

O(1)
Key Pattern to Remember

This problem combines two simple patterns:

1. Detect a sequential prefix
       ↓
nums[i] == nums[i-1] + 1

2. Find smallest missing number
       ↓
boolean[] seen

The overall flow is:

nums
 ↓
Find longest sequential prefix
 ↓
Calculate its sum
 ↓
Mark every number present in nums
 ↓
Start from sum
 ↓
First number not present = answer
Core intuition

First determine the target starting point (the prefix sum), then use a presence array to find the first missing value from that point onward.

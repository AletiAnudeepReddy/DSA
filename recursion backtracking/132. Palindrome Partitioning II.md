132. Palindrome Partitioning II
🧩 Problem

Given a string s, partition it into substrings such that every substring is a palindrome.

Unlike LeetCode 131, where we need to return all possible partitions, here we need to find:

The minimum number of cuts required to partition the string into palindromes.

Example
s = "aab"

Possible palindrome partitions:

"a" | "a" | "b"

This requires:

2 cuts

Or:

"aa" | "b"

This requires:

1 cut

Therefore:

Answer = 1
💡 Main Idea

This is basically Palindrome Partitioning (131) + Dynamic Programming.

At every index start, we try every possible ending position end.

s = "aab"

start = 0

Try:
"a"     → palindrome ✅
"aa"    → palindrome ✅
"aab"   → not palindrome ❌

For every palindrome we find, we recursively solve the remaining part.

The important question becomes:

What is the minimum number of cuts needed for the remaining string?

That's why we use DP.

🧠 State Definition

Let:

recur(start)

mean:

Minimum number of cuts needed to partition s[start...n-1] into palindromes.

For example:

s = "aab"

recur(0)

means:

Minimum cuts needed for "aab".

🔄 Transition

Suppose we are at:

start

and choose a palindrome:

s[start...end]

There are two cases.

Case 1: Palindrome reaches the end
end == n - 1

Example:

"aab"
   ↑

If "aba" itself is a palindrome, we don't need a cut after it.

Therefore:

cuts = 0
Case 2: There are characters remaining

Example:

"aa" | "b"
 ↑
palindrome

We need:

1 cut

and then solve:

"b"

So:

cuts = 1 + recur(end + 1)

Therefore:

recur(start)
=
min(
    cuts for every palindrome s[start...end]
)

Let's use:

s = "aab"

Indexes:

 0 1 2

Palindrome ✅

We make a cut:

"a" | "ab"

Remaining:

"ab"

"a"

"b" is a palindrome and reaches the end.

Therefore:

= 1 + 0

And:

But we haven't tried "aa" yet.

Back to recur(0)

Try:

We make:

We already know:

So:

1 + 0 = 1

Take the minimum:

min(2, 1) = 1

Therefore:

Answer = 1
🌳 Recursion Structure

For "aab":

                    recur(0)
                   /        \
              "a" /          \ "aa"
                 /              \
             recur(1)          recur(2)
             /                  |
          "a"                  "b"
           |                    |
       recur(2)                 0
           |
           0

"a" | "a" | "b" → 2 cuts

"aa" | "b" → 1 cut

Therefore:

min = 1
⚠️ Why Dynamic Programming?

Notice that the same state can be calculated multiple times.

For example:

recur(2)

can be reached through different partition choices.

Without DP:

recur(2)
recur(2)
recur(2)
...

We repeatedly solve the same problem.

So we store:

dp[start] = answer for s[start...n-1]

Then:

if (dp[start] != -1)
    return dp[start];

This converts the recursion into memoization.

✅ Your Brute-Force Code

Your current code is the recursive version:

class Solution {

    public int recur(String s, int start) {

        if (start == s.length()) {
            return 0;
        }

        int ans = Integer.MAX_VALUE;

        for (int end = start; end < s.length(); end++) {

            if (ispalin(s, start, end)) {

                int cuts;

                if (end == s.length() - 1) {
                    cuts = 0;
                } else {
                    cuts = 1 + recur(s, end + 1);
                }

                ans = Math.min(ans, cuts);
            }
        }

        return ans;
    }

    public boolean ispalin(String s, int l, int r) {

        while (l < r) {

            if (s.charAt(l++) != s.charAt(r--)) {
                return false;
            }
        }

        return true;
    }

    public int minCut(String s) {
        return recur(s, 0);
    }
}

The logic is correct, but for n = 2000, this can become too slow because of repeated recursive calculations.

🚀 Memoization / DP Solution

We simply add a dp array.

class Solution {

    private int recur(String s, int start, int[] dp) {

        if (start == s.length()) {
            return 0;
        }

        if (dp[start] != -1) {
            return dp[start];
        }

        int ans = Integer.MAX_VALUE;

        for (int end = start; end < s.length(); end++) {

            if (isPalin(s, start, end)) {

                int cuts;

                if (end == s.length() - 1) {
                    cuts = 0;
                } else {
                    cuts = 1 + recur(s, end + 1, dp);
                }

                ans = Math.min(ans, cuts);
            }
        }

        return dp[start] = ans;
    }

    private boolean isPalin(String s, int l, int r) {

        while (l < r) {

            if (s.charAt(l++) != s.charAt(r--)) {
                return false;
            }
        }

        return true;
    }

    public int minCut(String s) {

        int n = s.length();

        int[] dp = new int[n + 1];

        Arrays.fill(dp, -1);

        return recur(s, 0, dp);
    }
}
🔥 Even Better: Precompute Palindromes

There is one more optimization.

Currently, every time we do:

isPalin(s, start, end)

we may scan the substring.

Instead, we can precompute:

palindrome[i][j]

meaning:

Is s[i...j] a palindrome?

Then palindrome checking becomes:

if (palindrome[start][end])

in O(1).

Code
class Solution {

    public int minCut(String s) {

        int n = s.length();

        boolean[][] pal = new boolean[n][n];

        // Precompute palindromes
        for (int end = 0; end < n; end++) {

            for (int start = 0; start <= end; start++) {

                if (s.charAt(start) == s.charAt(end)
                        && (end - start <= 2 || pal[start + 1][end - 1])) {

                    pal[start][end] = true;
                }
            }
        }

        int[] dp = new int[n + 1];

        Arrays.fill(dp, Integer.MAX_VALUE);

        dp[0] = -1;

        for (int end = 1; end <= n; end++) {

            for (int start = 0; start < end; start++) {

                if (pal[start][end - 1]) {

                    dp[end] = Math.min(
                        dp[end],
                        dp[start] + 1
                    );
                }
            }
        }

        return dp[n];
    }
}
🧠 Understanding dp[0] = -1

This is a very useful trick.

Suppose:

s = "a"

"a" is already a palindrome.

We need:

0 cuts

Using:

dp[0] = -1

we calculate:

dp[1] = dp[0] + 1
      = -1 + 1
      = 0

Perfect.

For:

"aa" | "b"

the first palindrome "aa" gives:

dp[2] = dp[0] + 1
      = 0

Then "b" gives:

dp[3] = dp[2] + 1
      = 1

Therefore:

"aa" | "b"
       ↑
     1 cut
📊 Dry Run of Bottom-Up DP

For:

s = "aab"

Palindromes:

"a"   → [0,0]
"aa"  → [0,1]
"a"   → [1,1]
"b"   → [2,2]

Initialize:

dp[0] = -1
dp[1] = ∞
dp[2] = ∞
dp[3] = ∞
"a" → [0,0]
dp[1] = min(∞, dp[0] + 1)
      = min(∞, -1 + 1)
      = 0
"aa" → [0,1]
dp[2] = min(∞, dp[0] + 1)
      = 0
"a" → [1,1]
dp[2] = min(0, dp[1] + 1)
      = min(0, 1)
      = 0
"b" → [2,2]
dp[3] = dp[2] + 1
      = 0 + 1
      = 1

Final:

dp = [-1, 0, 0, 1]

Answer:

dp[3] = 1
⏱️ Complexity
Your recursive solution

Palindrome checking can take O(n) and there can be exponentially many recursive possibilities.

Time:  Exponential
Space: O(n) recursion stack
Memoization solution

There are n states, and for each state we try up to n ending positions.

Palindrome checking can itself take O(n).

Time:  O(n³)
Space: O(n)
Precomputed palindrome + DP solution

Palindrome preprocessing:

O(n²)

Minimum-cut DP:

O(n²)

Therefore:

Time:  O(n²)
Space: O(n²)

For n <= 2000, this optimized approach is much more suitable.

⭐ 131 vs 132

This is an important connection:

Problem	Goal	Technique
131. Palindrome Partitioning	Return all valid partitions	Backtracking
132. Palindrome Partitioning II	Find minimum cuts	DP
132 optimized	Quickly know whether substring is palindrome	Palindrome DP + Minimum-cut DP

The key transformation is:

131:
"Give me every possible palindrome partition."

132:
"Among all possible palindrome partitions,
